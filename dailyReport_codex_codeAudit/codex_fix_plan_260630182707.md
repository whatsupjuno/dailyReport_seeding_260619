## 3. 병렬 개발 전략

1. Worker 1: RBAC/그룹장 지정 검증
2. Worker 2: 제출 후 정합성
3. Worker 3: NCP timeout
4. Worker 4: 목록/입력 검증
5. Main: 통합, 충돌 해결, 전체 테스트, PR 제출, 완료보고서

파일 충돌 가능성이 있는 `ReportEditor.tsx`는 Worker 2가 소유하고 main이 최종 통합한다. `CommentDrawer.tsx`는 기존 dirty change가 있으므로 이번 PR에서 추가 수정하지 않는다. 기존 worktree의 `CommentDrawer.tsx` 변경은 Codex가 이번 턴에서 만든 변경이 아니므로, 포함 여부를 최종 diff와 PR 본문에 명시한다.
