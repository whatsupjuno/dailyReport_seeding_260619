## 1. 개요 · 목표 · 범위

### 1.1 4기능 요약

| # | 기능 | 한 줄 정의 | 영역 난이도 |
|---|------|-----------|------------|
| **#1** | 업무별 댓글 | 업무(task) 단위 우측 드로어 댓글. 작성·검수 공통, 댓글 수 + 미읽음 배지. | 중 |
| **#2** | 휴가/휴직/기타 사유 | `vacation_type`에 `휴직` 추가. `병가·휴직·기타`는 사유 필수, 모든 유형 최대 10,000자. 검수 읽기 카드. | 중 |
| **#3** | 업무별 개별 반려 | 검수자가 업무 행 단위 반려(행 표시만) + "부분 반려로 회신"(검수대기→반려 전이) 확인. 직원은 반려행만 파랑띠 편집, 나머지 잠금. 기존 보고서/시간대 반려와 공존. | **상** |

### 1.2 통합 설계 원칙 (전 기능 공통)

- **append-only 마이그레이션**: `0001~0004` 절대 수정 금지(운영 적용 완료). 변경은 항상 신규 파일.
- **추가형(additive) 우선**: 신규 컬럼/테이블/enum 값만 추가. 신규 컬럼은 NULL 허용, 필수성은 앱(도메인)에서 강제 + DB는 길이/정합 CHECK만.
- **DB 권위 검증**: UI 잠금(드로어 작성 영역, 반려행 잠금, 휴가 사유 필수)은 보조이며, 서버 mutation/route가 최종 가드(403/400/409 규약 유지).
- **enum은 `ADD VALUE`만**(`REMOVE`/`RENAME` 미지원). `migrate.ts`가 파일당 단일 `BEGIN/COMMIT`(scripts/migrate.ts:49-53)이므로 **enum 추가와 그 값 사용은 반드시 별도 파일**.
- **#4가 다른 기능의 기반**: #4의 단일 task 행 구조가 #1(행별 댓글 핀)·#3(행별 반려 밴드)의 렌더 기반. **#4는 task를 삭제·재생성하지 않고 `section_id`만 NULL로 작성/갱신** → #1 댓글 FK·#3 반려 FK가 끊기지 않음(전 기능 합의 사항, 리스크 R-1).
- **#4는 mutation의 잠금 판정 메커니즘 자체를 바꾼다** `[검증반영 B-3]`: 현재 `closeTask`/`updateTask`는 `report_sections` INNER JOIN으로 `s.locked`를 판정한다. section_id=NULL이면 INNER JOIN이 행을 탈락시켜 마감 자체가 불가능해진다. 따라서 #4는 단순 컬럼 추가가 아니라 **잠금 판정을 `daily_reports.status`(+#3 미해소 반려) 기반으로 전환하는 mutation 구조 변경**을 수반한다(R-17).

### 1.3 핵심 [가정] (전 기능 합의)

- **[A] #4 섹션 처리 = "강등(존치) + 파생 분류"**: `report_sections`/`tasks.section_id`를 삭제하지 않는다. 신규 task는 `section_id=NULL`로 작성하고, 오전/오후는 `completed_at`(KST 시각)으로 **조회 시 파생**. → 0004 교차 FK(`tasks_section_report_fk`, `MATCH SIMPLE`)는 NULL이면 검사 면제되므로 **재정의 불필요**. (대안 (a)안=FK 완화는 위험 R-6, 미채택.)
- **[B] 완료시각 SoT** = 신규 `tasks.completed_at timestamptz`. 분류 = `(completed_at AT TIME ZONE 'Asia/Seoul')`의 시 < 12 → 오전, ≥ 12 → 오후. KST 일관.
- **[C] 신규 report/section status enum 값 미추가**. #3 개별 반려는 `tasks` 컬럼 + 신규 테이블로 표현. #2만 `vacation_type`에 `휴직` 1개 추가.
- **[D] 댓글 미읽음** = per-user/per-task 워터마크(`comment_reads(user_id, task_id, last_read_at)`). 개별 read 플래그 아님.
- **[E] 댓글 길이** 10,000자(통합본은 본문 상한 10,000으로 #2와 정렬), 휴가 사유 10,000자.
- **[F] #4 컷오버 = 다음 영업일 0시부터 100% 새 모델**(in-place 변환 없음, 옵션 1). 컷오버 날짜는 사용자 지정(`SEEDING_MODEL_CUTOVER`). 진행 중 v1 보고서는 v1으로 마감(레거시 렌더러).
- **[G] 기능 플래그** 경량 도입: `FEATURE_TASK_COMMENTS`/`FEATURE_TASK_REJECT`/`FEATURE_BUCKET_MODE`. DB는 항상 먼저 마이그레이션(추가형이라 무해), UI 거동만 게이트 → 단계 배포 가능.
- **[H] 레거시 백필 분류 정확도 = best-effort** `[검증반영 C-3]`: 0009 백필은 `tasks.planned_start`(있으면 그 시각, KST) 우선, 없으면 섹션 종류 대표시각(morning 11:00 / afternoon 16:00 / night 20:00 / plan 10:00)으로 `completed_at`을 추정한다. plan 섹션 완결 task가 10:00로 뭉뚱그려질 수 있으나 이는 검수 표시에만 영향(권한·집계 무영향)이며 운영 의사결정에 무관 → 본 계획은 "분류 정확도는 best-effort, 검수 영향 없음"을 가정으로 못박는다.
- **[I] #3 상태전이 모델** `[검증반영 A-1]`: 행 반려(`rejectTask`)는 보고서 status를 **바꾸지 않고**(검수대기 유지) `task_rejections` insert + `tasks.reject_state='반려'`만 한다. `검수대기→반려` 전이는 검수자가 승인 모달에서 누르는 **"부분 반려로 회신"(`rejectReport`)에서 단 1회**만 발생한다. 두 함수를 절대 동일시하지 않는다.

## 3. 스키마 마이그레이션 통합본 (0005~0010)

### 3.1 `0005_task_comments.sql` (#1) — 공유 UNIQUE 포함

```sql
-- 업무별 댓글 (#1). 작성자/검수자 공통, per-user 읽음 워터마크.

-- (★공유) tasks 교차FK 토대: #1·#3가 함께 쓰는 (id, report_id) UNIQUE. 여기 한 번만 추가.
-- tasks.id 는 PK라 항상 유일 → 기존 운영 행 즉시 통과(백필 불필요).
ALTER TABLE tasks ADD CONSTRAINT tasks_id_report_uniq UNIQUE (id, report_id);

CREATE TABLE task_comments (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  task_id     bigint NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  report_id   bigint NOT NULL REFERENCES daily_reports(id) ON DELETE CASCADE, -- 비정규화: 보고서 단위 집계/권한 가드 단축
  author_user_id bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  author_role user_role NOT NULL,            -- 작성 당시 역할 스냅샷
  body        text NOT NULL,
  created_at  timestamptz NOT NULL DEFAULT now()
);
ALTER TABLE task_comments ADD CONSTRAINT task_comments_body_chk
  CHECK (length(trim(body)) > 0 AND length(body) <= 10000);
-- task 가 가리키는 report 동일 보고서 보장 (0004 교차FK 패턴 계승, 위 UNIQUE 활용)
ALTER TABLE task_comments ADD CONSTRAINT task_comments_task_report_fk
  FOREIGN KEY (task_id, report_id) REFERENCES tasks(id, report_id) ON DELETE CASCADE;
CREATE INDEX idx_task_comments_task ON task_comments(task_id, created_at);
CREATE INDEX idx_task_comments_report ON task_comments(report_id);

-- per-user/per-task 읽음 워터마크
CREATE TABLE comment_reads (
  user_id      bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  task_id      bigint NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  last_read_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (user_id, task_id)
);
```

### 3.3 `0007_vacation_reason_checks.sql` (#2) — 길이 + 보정 + 가역 백업

> `[검증반영 B-6]` placeholder 치환은 사용자 원문을 영구 덮어쓰는 **비가역** 작업이다. 보정 전에 빈사유 행을 별도 백업 테이블에 적재해 가역성을 확보한다. `'기타'`가 보정 범위에 포함됨을 확인했다(필수 유형 = 병가·휴직·기타).

```sql
-- 0006 커밋 후 실행되므로 '휴직' 라벨 안전 참조 가능.

-- (가드 1) 길이 초과 사유 사전 차단 — 운영 위반 0건 예상, 있으면 의도적 abort
DO $$ DECLARE n int;
BEGIN
  SELECT count(*) INTO n FROM daily_reports WHERE char_length(vacation_comment) > 10000;
  IF n > 0 THEN RAISE EXCEPTION '길이 초과 사유 % 건 — 수동 정리 필요', n; END IF;
END $$;

-- (1) 길이 상한 10,000자 (NULL 허용)
ALTER TABLE daily_reports ADD CONSTRAINT daily_reports_vacation_comment_len
  CHECK (vacation_comment IS NULL OR char_length(vacation_comment) <= 10000);

-- (★가역 백업) 빈 사유 필수유형 행을 placeholder로 덮기 전에 원본을 백업 테이블에 적재.
--   비가역 치환의 복구 경로 확보(롤백 §7.4 연계). 멱등: 이미 적재된 id 는 제외.
CREATE TABLE IF NOT EXISTS _vac_backfill_log (
  report_id        bigint PRIMARY KEY,
  old_vacation_comment text,
  vacation_type    text,
  logged_at        timestamptz NOT NULL DEFAULT now()
);
INSERT INTO _vac_backfill_log (report_id, old_vacation_comment, vacation_type)
SELECT id, vacation_comment, vacation_type::text
  FROM daily_reports
 WHERE is_vacation = true
   AND vacation_type IN ('병가','기타')   -- '휴직'은 신규값이라 기존 행 없음
   AND (vacation_comment IS NULL OR char_length(btrim(vacation_comment)) = 0)
ON CONFLICT (report_id) DO NOTHING;

-- (가드 2) 보정 대상 건수 로깅(운영 가시성)
DO $$ DECLARE n int;
BEGIN
  SELECT count(*) INTO n FROM _vac_backfill_log;
  RAISE NOTICE '빈 사유 필수유형 보정 대상 % 건 (백업 적재 완료)', n;
END $$;

-- (2) 필수 유형(병가·휴직·기타) 빈 사유 보정 후 CHECK.
--     기존 비필수였으므로 빈 사유 휴가 행이 운영에 존재 가능 → 먼저 placeholder 보정(idempotent).
UPDATE daily_reports
   SET vacation_comment = '(사유 미기재 — 기존 데이터)'
 WHERE is_vacation = true
   AND vacation_type IN ('병가','기타')   -- '휴직'은 신규값이라 기존 행 없음
   AND (vacation_comment IS NULL OR char_length(btrim(vacation_comment)) = 0);

ALTER TABLE daily_reports ADD CONSTRAINT daily_reports_vacation_reason_required
  CHECK (
    NOT ( is_vacation = true
      AND vacation_type IN ('병가','휴직','기타')
      AND (vacation_comment IS NULL OR char_length(btrim(vacation_comment)) = 0) )
  );
```

### 3.4 `0008_task_reject.sql` (#3)

```sql
-- 업무 행 단위 반려. 보고서/시간대 반려(report_events)와 공존. (tasks(id,report_id) UNIQUE 는 0005에서 추가됨)

ALTER TABLE tasks ADD COLUMN reject_state text;        -- NULL=정상, '반려'=행 반려
ALTER TABLE tasks ADD COLUMN rejected_at timestamptz;
ALTER TABLE tasks ADD CONSTRAINT tasks_reject_state_chk
  CHECK (reject_state IS NULL OR reject_state = '반려');

CREATE TABLE task_rejections (
  id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  task_id       bigint NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  report_id     bigint NOT NULL REFERENCES daily_reports(id) ON DELETE CASCADE,
  event_id      bigint REFERENCES report_events(id) ON DELETE SET NULL, -- 부분반려 회신 회차 그룹핑(회신 전 NULL)
  comment       text NOT NULL CHECK (length(trim(comment)) > 0),
  rejected_by   bigint REFERENCES users(id) ON DELETE SET NULL,
  rejected_at   timestamptz NOT NULL DEFAULT now(),
  resolved_at   timestamptz,                            -- 작성자 재제출 시 해소
  created_at    timestamptz NOT NULL DEFAULT now()
);
ALTER TABLE task_rejections ADD CONSTRAINT task_rejections_task_report_fk
  FOREIGN KEY (task_id, report_id) REFERENCES tasks(id, report_id);
-- 같은 task 미해소 반려 최대 1건 (부분 유니크; ON CONFLICT 추론용 동일 술어)
CREATE UNIQUE INDEX uq_task_rejection_open ON task_rejections(task_id) WHERE resolved_at IS NULL;
CREATE INDEX idx_task_rejections_report ON task_rejections(report_id) WHERE resolved_at IS NULL;
```

> 주: `tasks.reject_state/rejected_at`(빠른 행 렌더용 비정규화)와 `task_rejections`(이력·코멘트·해소 추적)를 **둘 다** 둔다. `reject_state`는 `task_rejections` 미해소 존재와 동기화(트랜잭션 내 동시 갱신). 단일 소스만 원하면 `reject_state`를 생략하고 LEFT JOIN 파생으로 대체 가능(구현 시 택1, 권장: 조인 파생으로 단일화하여 동기화 부담 제거).
>
> **상태전이 주의** `[검증반영 A-1/I]`: 이 테이블에 행을 insert하는 `rejectTask`는 `daily_reports.status`를 변경하지 않는다(검수대기 유지). `event_id`를 미해소 반려에 채우고 `검수대기→반려`로 전이하는 것은 회신 함수 `rejectReport` 1회뿐이다.

### 3.5 `0009_single_list_model.sql` (#4) — 컬럼·백필·CHECK

> `[검증반영 C-3/[H]]` 백필 대표시각은 `planned_start` 우선, 없으면 섹션 종류 대표시각.

```sql
-- F4: 단일 목록 + 완료시각 자동분류. 섹션은 표시 전용으로 강등(테이블 존치).
-- 실행 순서: 컬럼추가 → section_id NULL허용 → 백필 → CHECK ADD → 인덱스 → model_version

ALTER TABLE tasks ADD COLUMN completed_at timestamptz;        -- 마감 시각(KST 분류 기준). NULL=미마감
ALTER TABLE tasks ADD COLUMN is_night     boolean NOT NULL DEFAULT false;
ALTER TABLE tasks ALTER COLUMN section_id DROP NOT NULL;      -- 신규 task는 NULL. 0004 교차FK(MATCH SIMPLE)는 NULL 면제

-- 레거시 백필: 완결/지연 task의 completed_at 추정.
--   planned_start(있으면 그 시각) 우선, 없으면 섹션 종류 대표시각(오전/오후 보존). 모두 KST.
UPDATE tasks t
   SET completed_at = COALESCE(
         CASE WHEN t.planned_start IS NOT NULL
              THEN (r.report_date + t.planned_start) AT TIME ZONE 'Asia/Seoul' END,
         (r.report_date + CASE s.kind
             WHEN 'morning' THEN time '11:00' WHEN 'afternoon' THEN time '16:00'
             WHEN 'night' THEN time '20:00' ELSE time '10:00' END) AT TIME ZONE 'Asia/Seoul')
  FROM report_sections s, daily_reports r
 WHERE s.id = t.section_id AND r.id = t.report_id
   AND t.status IN ('완결','지연') AND t.completed_at IS NULL;

UPDATE tasks t SET is_night = true             -- 레거시 night 섹션 task
  FROM report_sections s WHERE s.id = t.section_id AND s.kind = 'night';

-- (가드) 백필 누락(완결인데 completed_at NULL) 0건 확인 후 CHECK
DO $$ DECLARE n int;
BEGIN
  SELECT count(*) INTO n FROM tasks WHERE status IN ('완결','지연') AND completed_at IS NULL;
  IF n > 0 THEN RAISE EXCEPTION '완결/지연인데 completed_at NULL % 건 — 백필 점검', n; END IF;
END $$;
ALTER TABLE tasks ADD CONSTRAINT tasks_completed_at_chk
  CHECK ((status IN ('완결','지연')) = (completed_at IS NOT NULL));

CREATE INDEX idx_tasks_completed ON tasks(report_id, completed_at);
ALTER TABLE daily_reports ADD COLUMN model_version smallint NOT NULL DEFAULT 1; -- 1=레거시 섹션, 2=단일목록
```

> 주: `planned_start` 컬럼명/타입은 구현 시 실제 스키마(`tasks`)와 대조 후 확정. 없거나 타입이 다르면 `[H]` 가정대로 섹션 대표시각 단독 백필로 폴백(분류 영향 best-effort).

### 3.6 교차 FK / 무결성 주의 (통합)

- **`tasks(id, report_id) UNIQUE`는 0005에서 단 1회.** #1·#3 둘 다 의존하나 중복 추가 금지(이미 존재 시 ALTER 실패). 두 기능 모두 이 UNIQUE 위에 교차 FK를 건다.
- **0004 `tasks_section_report_fk`(MATCH SIMPLE)**: #4가 `section_id=NULL`로 task를 만들면 복합 FK 중 하나가 NULL → 검사 면제 → **재정의 불필요**. 0009 적용 후 "section_id=NULL task INSERT가 교차FK 통과" 단위 검증 필수.
- **enum**: #2의 `휴직`만 추가. 0006(단독) → 0007(사용) 순서를 파일명 정렬이 보장.
- **CHECK는 백필 뒤 ADD**: 0007(필수 사유)·0009(completed_at)는 모두 보정/백필 후 CHECK + `DO $$ RAISE` 가드로 위반 시 abort.

## 5. #4 모델 교체 데이터 마이그레이션 · 하루경계 컷오버 전략 (강조)

운영에 **오늘 보고서가 섹션 모델로 이미 존재**하므로 in-place 일괄 변환은 금지. 다음 4축으로 무중단 전환한다.

### 5.1 이중 렌더러 + model_version 표식 + 날짜 컷오버

1. **컷오버 상수** `src/lib/config.ts`의 `NEW_MODEL_CUTOVER_DATE`(env `SEEDING_MODEL_CUTOVER`, ISO date). 값은 **사용자가 추후 지정**.
2. **신규 생성분만 새 모델**: `getOrCreateReport`가 `report_date >= CUTOVER`면 `model_version=2`(plan 섹션 미생성), 그 전이면 종전대로 v1(plan 섹션 생성).
3. **레거시 표시**: `model_version=1`(또는 `report_date<CUTOVER`) 보고서는 `LegacyReportEditor`(현 ReportEditor 동결본) + `computeLegacyWriteMode`/`stepperFor`/휴가 섹션맵(legacy 모듈, B-4)로 기존 섹션 흐름 보존. 검수도 레거시는 섹션 렌더(ReviewDetail의 `model_version=1` 분기).
4. **하루 경계(옵션 1, 채택)**: 컷오버 당일 **이미 v1으로 생성된 오늘 보고서는 끝까지 v1**으로 마감. 즉 컷오버는 "**다음 영업일 0시(KST)부터 100% 새 모델**". 진행 중 보고서 깨짐 0. (옵션 2=클린 컷 in-place 변환은 미채택, 위험.)

### 5.2 레거시 백필 (0009 내장, §3.5)

- 완결/지연 task의 `completed_at`을 `planned_start` 우선(있으면), 없으면 섹션 종류 대표 시각(morning 11:00 / afternoon 16:00 / night 20:00 / plan 10:00, KST)으로 채워 **오전/오후 분류 보존**(best-effort, `[H]`). night 섹션 task는 `is_night=true`.
- `DO $$ RAISE` 가드로 백필 누락(완결인데 NULL) 0건 확인 후 `tasks_completed_at_chk` ADD → 마이그레이션이 안전 실패 가능.
- 도메인 `classify`는 폴백 규칙 내장: `completed_at` 있으면 시각, 없으면(이론상 없음) 안전 처리(todo).

### 5.3 컷오버와 마이그레이션의 분리 배포

- **0009는 컷오버와 독립**: 컬럼 추가 + 백필만이라 즉시 적용해도 v1 동작 불변(신규 코드가 `model_version`으로 분기). → **순서: ① DB 마이그레이션 선행 배포 → ② 코드 배포(플래그 OFF=섹션 유지 가능) → ③ `SEEDING_MODEL_CUTOVER` env 설정/플래그 ON.**
- **기능 플래그 단계 배포(권장)**: 1차 = 마이그레이션 + #1/#2/#3 ON, **#4 OFF**(섹션 모델 유지) → 가장 안전. 2차 = 운영 보고서 자연 소진(다음날) 후 **#4 ON**.

### 5.4 롤백 안전성 (모델 관점)

- 0009는 추가형이라 **앱 빌드만 롤백해도 구코드는 신규 컬럼 무시 → 정상**(DB 무손). 단 (a)안(FK 완화) 채택 시 이 안전성이 깨지므로 **(b)안 강제**.
- `SEEDING_MODEL_CUTOVER` env만 제거하면 신규 생성이 다시 v1 → 기능 사실상 비활성(데이터 안전 롤백 경로).
- **비가역 지점 3종** `[검증반영 C-2]`(§7.4·DEPLOY.md에 명문화):
  1. `model_version=2` task에 `section_id=NULL`이 생긴 뒤엔 `section_id NOT NULL` 복구 불가 → **코드 배포 후 down 마이그레이션 불가**.
  2. 0007 `vacation_comment` placeholder 치환은 원문 영구 덮어쓰기 → `_vac_backfill_log` 백업 테이블(§3.3) 없으면 복구 불가.
  3. enum `휴직` 제거 불가(PG 한계, 무해).

- **단계 배포**: 1차 플래그 `FEATURE_BUCKET_MODE=off`(섹션 유지) + #1/#2/#3 ON. 2차 `SEEDING_MODEL_CUTOVER` 설정 + `FEATURE_BUCKET_MODE=on`.

### 7.3 배포 전 운영 사전 점검 쿼리
- `SELECT count(*) FROM daily_reports WHERE char_length(vacation_comment)>10000;` → 0 (0007 안전)
- `SELECT count(*) FROM daily_reports WHERE is_vacation AND vacation_type IN ('병가','기타') AND btrim(coalesce(vacation_comment,''))='';` → **빈 사유 보정 대상 규모 파악**(0007 placeholder 치환·백업 대상) `[검증반영 B-6]`
- `SELECT count(*) FROM tasks WHERE status IN ('완결','지연') AND completed_at IS NULL;` → 백필 규모 파악

### 7.4 롤백 (`deploy/rollback.sh` 신규)
- **`rollback.sh app`(1차, 권장)**: `.next`만 직전 빌드로 복귀 + restart. **마이그레이션이 모두 추가형이라 DB 그대로 둬도 구코드 정상**. `SEEDING_MODEL_CUTOVER` 제거 시 신규 생성 v1 복귀.
- **`rollback.sh db`(최후)**: `pg_restore --clean --if-exists`로 dump 복원. **백업 이후 입력된 당일 데이터 손실** → 영업시간 외 + 즉시 검증으로 윈도우 최소화.
- **비가역 3종 명문화** `[검증반영 C-2]`(DEPLOY.md):
  1. `model_version=2` + `section_id=NULL` 생성 후 down 마이그레이션 불가.
  2. 0007 `vacation_comment` placeholder 치환은 비가역 — 복구는 `UPDATE daily_reports d SET vacation_comment=l.old_vacation_comment FROM _vac_backfill_log l WHERE d.id=l.report_id;`로 백업 테이블에서만 가능. 백업 테이블 없으면 복구 불가.
  3. enum `휴직` 제거 불가(PG 한계, 무해).
- DEPLOY.md에 #3 잔존 미해소 반려 정리 가이드(`UPDATE task_rejections SET resolved_at=now() WHERE resolved_at IS NULL`) 추가.
