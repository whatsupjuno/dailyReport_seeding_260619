브리프가 **자기 수용기준 11개(`개발지시서.md:304-314`)** 를 직접 제공했는데도 이를 **추적 가능한 게이트로 전환하지 않았고**, v2를 "리팩터"가 아니라 **단일 커밋 전면 재작성(git `b0f8d8c`)** 으로 진행하면서 **구표면↔신표면 패리티 대조와 제거 원장이 없어** 명세에 있는 기능(커뮤 첨부 등)이 "단순화"로 위장된 채 증발했고, **테스트가 명세가 아닌 "만든 것"만 검증**해 누락을 회귀로 잡지 못했으며, **완성도 감사가 DoD가 아니라 사용자 지적 후 반응적으로** 가동됐다.

## ② 무슨 일이 있었나 (숫자·증거)

- **요구는 명문화돼 있었다.** 브리프는 §4.2에서 커뮤니케이션 "파일첨부(선택)"을 명시(`개발지시서.md:110-111,121`), 데이터모델·API도 `communication_attachments` / `attachments[]`를 정의(`02-데이터모델.md:34,63`, `03-API-화면매핑.md:153`). 즉 **빠진 것은 미명세가 아니라 구현 누락**이다.
- **브리프는 DoD까지 줬다.** `개발지시서.md:304-314`에 `- [ ]` 수용기준 11개(반려행 흐림·검수 동적노드·⋯메뉴 수정/삭제·커뮤 추가폼·근태 10,000자·댓글 슬라이드인·≤720 반응형·토큰 일치 등). **구현 후에도 이 박스들은 추적/검증되지 않았다.**
- **사전 경고도 있었다.** `디자인v2-검증리포트.md`가 **구현 착수 전** 이미 4기능 전반의 `[부분]/[누락]` 수십 건을 적시(예: 기능4 "⋯ 시각수정→재분류 전체 누락", "마감 임박 인디케이터 누락"; 기능3 "직원 작성화면 task 단위 편집 미구현"). 그런데 동일 누락이 구현에서 재현됐다.
- **결과.** 세션 내 완성도 감사에서 109건(과반 P2 디자인 충실도 + 핵심 P1 기능). 사용자가 "커뮤니케이션 기록에 첨부 넣는 게 전혀 안 보인다"고 직접 지적하고 나서야 완성도 점검이 시작됐다.
- **구분 정리(원장):** 의도적 제거(섹션모델·강제마감·정성지표AI·OTP연기 등)는 누락이 아니다 → `PARITY.md` A. 진짜 누락(커뮤 첨부/업무 수정·삭제/관리 CRUD)은 복구 대상 → `PARITY.md` B. 디자인 충실도 → `PARITY.md` C.

## ③ 근본 원인 (분류·증거) — "왜 안 보였나"

표면 증상(첨부 버튼 없음)이 아니라 **프로세스 결함**을 짚는다. 각 항목은 `원인 → 그래서 무엇이 빠짐 → 증거`.

**RC-1. 명세↔구현 추적표(traceability matrix) 부재 → 빠진 걸 셀 방법이 없었다.**
브리프가 수용기준 11개를 줬으나(`개발지시서.md:304-314`) 이를 "요구 → 구현위치 → 테스트 → 상태" 행으로 전환한 표가 없었다. 표가 없으니 "다 했다"의 분모가 머릿속에만 있었고, ⋯메뉴(`:309`)·커뮤 추가폼(`:310`) 같은 줄이 누락돼도 빨간불이 켜지지 않았다.

**RC-2. "리팩터"가 아닌 "재작성(rewrite)" 프레이밍 → 기억나는 것만 이식, 구표면 패리티 대조 없음.**
git `b0f8d8c`가 ReportEditor/ReviewDetail를 **단일 커밋 전면 재작성**. v1에 존재하던 첨부 결선(`5b99c9e feat: attachments(file/url)…`)이 신표면으로 이식되지 않았다. 재작성의 멘탈모델은 "핵심 4기능(단일목록·댓글·반려·휴직)"에 집중했고, 보조 어포던스(첨부·수정·삭제)는 구표면과 대조하지 않아 증발했다.

**RC-3. "의도적 단순화"와 "사고적 누락"의 혼동 → 무엇을 왜 뺐는지 기록(원장)이 없었다.**
v2는 실제로 섹션모델·강제마감 등을 의도적으로 뺐다(정당). 제거 원장이 없으니 커뮤 첨부 누락이 그 정당한 단순화의 일부처럼 **위장**됐다. 사용자 지적 전까지 "뺀 것"과 "빠뜨린 것"을 구분할 근거가 부재했다(이번에 `PARITY.md`로 분리).

**RC-4. 디자인 충실도가 수용기준이 아니라 암묵적 느낌으로 다뤄짐.**
`디자인v2-검증리포트.md`가 구현 전 P2 누락을 다수 경고했지만, 이를 **화면별 번호 체크리스트·시각/상태 테스트**로 승격하지 않았다. "느낌상 디자인대로"는 게이트가 아니므로, 반려행 흐림(`:306`)·검수 동적노드(`:308`)·반응형(`:313`)이 그대로 빠졌다.

**RC-5. 테스트가 명세가 아니라 "내가 만든 것"을 검증 → 없는 기능은 테스트가 못 잡는다(자기참조적 커버리지).**
e2e/유닛은 구현된 경로만 덮었다. 커뮤 첨부에 대한 존재/계약 테스트가 아예 없었으므로(이번에 `comm.spec.ts`에 추가), "빠졌다"가 빨강으로 드러나지 않았다. 커버리지 숫자(유닛 65·e2e 24)는 높았지만 **미구현 기능은 분모에 없었다.**

**RC-6. 검증이 반응적 → 완료 정의(DoD)에 완성도 감사가 없었다.**
예외 감사(46건)·사용성 감사(41건)는 훌륭했으나 **사후**에 돌았다. "완료 선언" 직전 필수 단계로서의 완성도(누락) 감사가 DoD에 없었다. 그래서 사용자의 "안 보인다" 한마디가 트리거가 됐다.

**RC-7. 단독 작성자 자기검토 → 누락을 만든 동일 멘탈모델이 "완료"를 승인.**
빌더와 구조적으로 분리된 "무엇이 빠졌나"만 보는 독립 리뷰어가 없었다. 같은 사람이 "핵심 4기능 됐다 = 완료"로 닫았고, 그 멘탈모델의 사각(보조 어포던스)이 그대로 통과됐다.

## ④ 재발방지 대책 (절차·산출물·게이트)

추상론 금지. 이 레포에 바로 적용한다. 각 대책에 **산출물 / 책임 / 시점**을 명시.

**M-1. 명세 인벤토리 + 추적표 도입 → DoD = 전 행 해소.** (RC-1, RC-4 대응)
- 산출물: `docs/TRACEABILITY.md`(아래 템플릿). 착수 전 브리프+디자인의 모든 요구를 `REQ-NNN`으로 추출 — 특히 `개발지시서.md:304-314`의 11개 수용기준을 1행씩 등재. 각 행: 요구·근거(file:line)·구현위치·테스트·상태(`done`/`intentional-removed→PARITY`/`deferred`).
- 게이트: **모든 행이 `done` 또는 명시 사유로 닫히기 전엔 "완료" 선언 금지.**
- 시점: 재작성/대형 기능 착수 직후(코드 전). 책임: 빌더가 작성, 리뷰어가 검수.

**M-2. 재작성 패리티 디프 — 구표면 인벤토리 vs 신표면.** (RC-2, RC-3 대응)
- 산출물: 재작성 전 **구표면 인벤토리 자동 추출** — 라우트(`src/app/**/route.ts`, `page.tsx`), 컴포넌트, `data-testid`, API 엔드포인트, UI 어포던스(버튼/메뉴). 신표면과 diff.
- 규칙: diff에서 사라진 항목은 **100% `PARITY.md`에 분류**(의도적 제거 A / 복구 대상 B). 빈칸 금지.
- 시점: 재작성 직전 + 직후 2회. 책임: 빌더.

**M-3. 디자인 충실도 = 화면별 번호 체크리스트 + 시각/상태 테스트.** (RC-4 대응)
- 산출물: `디자인v2-검증리포트.md`의 `[부분]/[누락]`을 화면별 체크 항목으로 승격(작성/검수/목록/댓글/관리/셸·로그인). 각 항목에 Playwright 요소 존재/상태 단언(예: 반려행 파란 띠 클래스, 임박 칩 testid, ≤720 카드 전환).
- 게이트: 충실도 체크리스트 미통과 항목은 `PARITY.md` C에 등재되거나 수정되기 전 미완.

**M-4. DoD 게이트에 "완료 선언 전" 완성도 감사 상시화.** (RC-6 대응)
- 절차: 완료 직전 필수 단계로 **멀티에이전트 적대 감사**(존재/계약/충실도 3축)를 사전에 돌린다 — 지적 후가 아니라 전. 산출물은 추적표의 미해소 행 목록.
- 시점: "배포/완료" 직전. 책임: 빌더가 트리거, 독립 리뷰어가 판정.

**M-5. 독립 적대 리뷰어(빌더와 분리) — "무엇이 빠졌나"만 본다.** (RC-7 대응)
- 절차: 예외·사용성 감사를 **사후가 아닌 사전 DoD 단계**로 이동. 빌더와 다른 컨텍스트(별도 세션/에이전트)가 명세 대비 누락만 전담.

**M-6. 제거 원장 `PARITY.md` 유지 — 가역·감사가능.** (RC-3 대응)
- 규칙: v1/명세 표면을 v2에서 뺄 때마다 사유와 함께 행 추가. 본 사건의 산출물로 초안 작성 완료.

**M-7. 테스트가 명세를 단언 — 추적표에서 파생.** (RC-5 대응)
- 규칙: `TRACEABILITY.md`의 각 기능 REQ는 **존재/계약 e2e**를 하나 이상 가진다. 미래에 그 기능이 빠지면 테스트가 빨강. (예: 커뮤 첨부 칩·⋯메뉴·관리 수정.) 커뮤 첨부는 이미 `tests/e2e/comm.spec.ts`에 추가됨.
