# Seeding 개선계획 — "기능적·사용성 완벽" 도달 로드맵

> 본 문서는 7개 차원 감사 발견 + 완성도 비평을 종합한 **실행 계획**이다. 코드 수정은 포함하지 않으며, 각 항목은 file:line 또는 디자인/브리프 근거를 유지한다. 모르는 부분은 "모름"으로 표기했다.
> 작성 시점에 다음 핵심 근거를 코드로 직접 재검증함: `comments.ts:42-44`(admin→canWrite=true), `review.ts:95-99`(approve가 행반려 일괄 해소), `session.ts:23`(secure=https시만), `service.ts:13-34`(고정 login_code, 발급/만료 없음).

---

## 1. 목표·원칙

**완성 정의(DoD)**
- 본 계획의 **개선 항목 표(§3) 전 행이 해소**되고, 각 항목이 §4 배치의 수용기준+테스트로 게이트되어 통과한다.
- "기능적 완벽" = 사용자가 도달 가능한 모든 동선에서 막힘/데이터 손실/권한 위반이 없다.
- "사용성 완벽" = 디자인 SoT 충실 + 접근성(포커스/aria/대비) + 상태 일관성(로딩/에러/빈/저장표시) 충족.

**원칙**
1. **디자인 SoT 충실** — 디자인 버전 충돌(v2 vs v23) 항목은 §5 결정 후에만 착수. SoT 미확정 항목은 "결정 필요"로 보류.
2. **재발방지(독립 적대 감사)** — `재발방지-대책.md`의 추적표 원칙을 따른다. 각 배치 완료 시 PARITY.md 해당 행을 갱신(B→해소, C→해소).
3. **의도적 제거(PARITY A)는 범위 밖** — I-1(섹션모델), I-2(강제마감), I-3(정성지표 AI), I-5(프로필변경)는 본 계획 대상이 아니다. 단 **I-4(OTP 연기)와 I-7(task row 첨부)은 디자인 v23/운영보안 관점에서 재분류 후보**이므로 §5 결정 항목으로 올린다.
4. **P0는 정말 막힘/보안/데이터만** — 디자인 충실도·미세 UX는 P2.

## 2. 현황 스냅샷

**최근 반영(다시 누락으로 잡지 않음)**
- 업무행 ⋯메뉴 수정/삭제(R-4), 커뮤니케이션 파일첨부(R-1/R-2삭제/R-3), 최상위 셀프승인 폴백(`ownerHasOtherReviewer`).
- 자동분류 토스트, 근태 필수 빨강 `*`·10,000자 빨강안내(`ReportEditor.tsx:510,515-518`), 401→/login 유도, 세션 self-purge(`session.ts:44`), 댓글 author SET NULL(0010), 이월 토스트 정직화.

**남은 큰 덩어리**
- **권한 게이팅 누수(P0)**: 관리자가 댓글 작성 가능(`comments.ts:44`←`review.ts:29`). 관리자 행반려도 노출(같은 근원).
- **인증/전송 보안(P0)**: 고정 4자리 코드(발급/만료 없음), 운영 평문 HTTP(secure=false). 둘 다 PARITY A 연기와 충돌 → 정책 재확인.
- **승인 시맨틱 충돌(P1)**: `approveReport`(review.ts:95-99) 승인=반려 일괄 해소 vs 디자인 수용기준 :307/브리프 L164 부분반려 회신(보존). 명세 정면 위반.
- **자동화 결선(P1)**: 반려 알림 메일 미발송, night_close/reminder cron 미등록, dedup 멱등키 부재.
- **관리 CRUD(P1)**: 추가만 가능. 수정/active토글/그룹·그룹장 관리 없음(R-5). → 비활성 세션 일괄폐기·소프트삭제 epic의 전제.
- **목록/반응형(P1)**: 통계 4카드·직원 반려 배너·페이지네이션 없음, ≤720px 표→카드 미전환.
- **a11y 공통(P1)**: 포커스 트랩·ESC·aria-live·aria-pressed·폼 label 연결 전무.
- **디자인 충실도(P2 다수)**: 작성 헤더/반려모드/야간 콜아웃, 검수 카운트요약/타임라인/원형배지, 댓글 띠/스크롤.

## 6. 리스크·롤백

**라이브 영향(운영 데이터 3+건, 격리DB, systemd, NCP cron)**
- Batch 1(권한): 관리자 동선 변경. 셀프승인 폴백 회귀 필수 — 폴백 깨지면 1인 운영 검수 불능. **롤백**: commentAccess/viewerRole 게이팅 단일 커밋이라 revert 용이.
- Batch 3(승인 시맨틱): **기존 승인된 보고서의 반려 데이터는 이미 소멸**되어 소급 복원 불가. 정책 전환은 전환 이후 데이터에만 적용. 배포 전 현행 동작 명시 공지.
- Batch 4(자동화): cron 추가는 중복발송 위험 → **dedup_key UNIQUE를 cron 결선보다 먼저 배포**. night_close 동적시각 오류 시 발송 폭주 가능 → dry-run 로그 먼저.
- Batch 5(관리 CRUD): active 토글+세션 일괄 DELETE는 실수 시 대상자 강제 로그아웃. 확인 모달 필수.

**마이그레이션 필요 항목**
- `notifications` dedup_key 컬럼+UNIQUE(Batch 4) — 기존 행 backfill 또는 nullable+부분 인덱스.
- 관리 CRUD/그룹 leader 관련은 스키마 대체로 존재(`users.active`, `groups.leader_user_id`) — 신규 마이그레이션 최소.

- OTP 전환(P0-2) 시 `auth_otps`는 0001에 존재 — 스키마 변경 없이 결선.

**롤백 전략**
