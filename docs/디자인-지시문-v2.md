# Seeding 일일 업무 보고 — 기능 확장 화면 4종 (Claude Design 지시문 v2)

기존 **Seeding 일일 업무 보고 시스템**의 디자인을 확장한다. 아래의 **디자인 토큰·톤·컴포넌트를 그대로 따르고**, 새 색·새 폰트·새 컴포넌트 도입을 금지한다. 모든 UI는 **한국어**, **PC 기본 + 720px 이하 모바일 반응형**으로 만든다. 아래 4개 기능을 각각 **독립 HTML 화면**으로 생성하되, 모두 한 디자인 시스템 안에서 일관되게 보이도록 한다. (코드·DB·API가 아니라 **순수 화면 디자인**만 만든다. `[보강]` 표기는 원본 디자인에 없던 합리적 보강이다. `[기존→변경]` 표기는 기존 컴포넌트를 무엇에서 무엇으로 바꾸는지를 가리킨다.)

## 공통 토큰 요약 (모든 화면 공통 · 반드시 일치)

- **폰트**: Pretendard. 숫자·시각은 `tabular-nums`(이하 "tnum"), 본문 줄바꿈은 `word-break: keep-all`.
- **배경/텍스트**: 배경 `#F7F8FA` · 텍스트 `#1A1F2B` · 보조 `#6B7280` · 흐림 `#9AA1AE` · 본문강조 `#3A4150`.
- **경계/카드**: 경계 `#E2E5EB`·`#CBD0D9`. 카드 = 흰색 + 1px `#E2E5EB` + radius **12** + 옅은 그림자 `0 1px 3px rgba(16,24,40,.08)`. 라운드 8/12/16, pill 9999.
- **포인트**: `#3B5BDB` (연한배경 `#EEF2FF` / 잉크 `#2F49B0`). 포커스 링 `0 0 0 3px rgba(59,91,219,.35)`.
- **상태색(아이콘+라벨 pill, bg/border 짝)**: 완결 `#1F9254`/bg `#E7F6EC`/border `#BBE5C8` · 진행중·제출 `#2563EB`/bg `#E6EEFD`/border `#BBD0F7` · 지연·반려 `#DC2626`/bg `#FCEBEB`/border `#F5C2C2` · 지연임박 `#D97706`(또는 `#B45309`)/bg `#FDF3E5`/border `#F6D9A8` · 검수대기 `#B7860B`/bg `#FBF4DA`/border `#EFE0A6` · 휴가·회색 `#6B7280`/bg `#F1F2F4`.
- **아바타**: 이니셜 1글자 원형. 포인트 톤 `#E0E7FF`/`#2F49B0`(그룹장·관리자), 중립 톤 `#EFF1F5`/`#3A4150`(직원).
- **버튼**: 포인트 채움 `#3B5BDB`/흰글자 · 고스트 흰배경+`#CBD0D9` 보더 · 비활성 흐림 톤. 라운드 7/8.
- **오버레이/모달**: 오버레이 `rgba(16,24,40,.45)`. 패널 흰색 radius 16 + 그림자 `0 12px 28px rgba(16,24,40,.16)` + 헤더 X(`#9AA1AE`, 20px) + sticky 푸터. **모바일에서 모달/사이드 패널은 풀스크린 또는 바텀시트**로 전환.
- **z-index·sticky 기준(중요)**: 단정 수치 대신 **각 화면의 기존 sticky 헤더 높이**를 기준으로 한다. 앱 상단바는 `top:0`이며 z-index와 높이는 기존 값을 그대로 따른다(작성 화면 헤더 56px, 검수 우측 사이드 sticky 기준 64px 등 화면마다 다름). 새로 띄우는 오버레이·드로어·시트는 **기존 반려 모달(z-index 200) 위**에 오도록 쌓되, 오버레이는 200대, 그 위 패널은 그보다 한 단계 위로 둔다. 절대 수치를 새로 단정하지 말고 "기존 sticky 헤더 높이 기준, 반려 모달 위"로 적용한다.
- **공통 위젯**: 커스텀 스크롤바(thumb `#CBD0D9`, radius 9999), 스피너(`spin`)·로딩 점멸(`dotpulse`), 점선 첨부 버튼, sticky 액션바(`rgba(255,255,255,.92)` + blur + 상단 1px 보더). 반응형 유틸 `.pc-only`/`.sm-only`, 브레이크포인트 720px(검수 2단 그리드는 기존대로 1000px에서 1단 전환).
- **역할**: 직원(작성) / 그룹장(검수, 자기 그룹) / 관리자. **권한별로 보이는 요소가 다르며 각 기능에 명시**한다.

# 기능 1 — 단일 업무 항목별 댓글 (우측 사이드 드로어)

작성 화면과 검수 화면의 **개별 업무행에 "댓글" 기능**을 추가한다. 업무행의 댓글 버튼을 누르면 화면 오른쪽에서 드로어가 슬라이드-인되어 **업무 1건 = 댓글 스레드 1개**를 시간순으로 보여준다.

### 진입점
- **업무행 우측 액션 영역에 댓글 버튼**을 추가한다.
  - 작성 화면 업무행은 **마감 버튼 유무로 분기**한다(기능 4에서 완료 행은 마감 버튼이 사라지므로):
    - **미완료 행**: 기존 `마감` → **`댓글`** → `⋯` 순서. 즉 `[마감]→[댓글]→[⋯]`.
    - **완료 행(마감 버튼 없음)**: **`댓글` → `⋯`** 순서. 즉 `[댓글]→[⋯]`로, `⋯` 메뉴 바로 왼쪽 첫 액션.
  - 검수 화면 업무행(읽기 전용): 행 우측에 댓글 버튼만 단독으로 **항상 노출**.
- 버튼 형태: 말풍선 line 아이콘(stroke-width 1.4~1.6, round) + 댓글 수 배지. 고스트 정사각 버튼(높이 28~30px, radius 7, 흰배경, 보더 `#E2E5EB`, 아이콘 `#6B7280`).
  - 댓글 1개 이상: 라벨 옆 숫자 pill(연한배경 `#EEF2FF`/`#2F49B0`/radius 9999/11px 700). 0개면 숫자 없이 흐림(`#9AA1AE`) 말풍선만.
  - **안읽음 강조 [보강]**: '안읽음'은 본인이 아직 열지 않은 새 댓글이 있을 때만을 가리킨다. 판정 로직은 디자인 범위 밖이므로 **시각 규칙만 정의**한다 — 안읽음 있음 = 포인트 채움 pill(`#3B5BDB` 채움, 흰 숫자), 모두 읽음 = 연한배경 pill(`#EEF2FF`/`#2F49B0`).
- 클릭 시 오버레이(`rgba(16,24,40,.45)`) + 드로어 슬라이드-인(translateX, .2s ease). 헤더는 클릭한 업무행 데이터로 채운다.

### 레이아웃
- **PC(>720px)**: 화면 우측 고정 드로어, 폭 **400px**, 높이 `100vh`. 드로어 `top`은 **각 화면의 기존 sticky 헤더 높이에 맞춰** 시작한다(작성 화면 56px·검수 화면 64px 등 화면마다 다름). z-index는 **기존 반려 모달(200) 위**에 오게 한다(오버레이 200대, 드로어는 그보다 위). 흰배경 + 좌측 1px `#E2E5EB` + 좌측 그림자 `-4px 0 16px rgba(16,24,40,.08)`. 검수 화면에서는 우측 사이드 패널(360px)을 **밀지 않고 그 위에 오버레이**로 뜬다.
- **모바일(≤720px)**: 하단 **바텀시트**(폭 100%, max-height 90vh, 상단 radius `16 16 0 0`, 상단 드래그 핸들 36×4 `#CBD0D9` [보강]). 키보드가 올라오면 컴포저가 키보드 위로 밀려 가려지지 않게. 풀스크린(100vh) 확장 가능 [보강].
- 수직 3분할(flex column): **헤더(고정) → 댓글 목록(flex:1, 세로 스크롤) → 입력 컴포저(고정)**.

### 구성요소
- **헤더(고정)**: 좌측 — 윗줄에 프로젝트칩(있을 때 `#EEF2FF`/`#2F49B0`/radius 6) + 작은 "댓글" 라벨, 아랫줄에 업무명(15px 700, 1줄 말줄임) + 소속 시간대(오전/오후/야간) + 상태배지. 상태배지는 **기존 task 배지 규격(font 11px/600, padding 2px 7px, radius 6)을 그대로** 사용한다(임의 축소 금지). 우측 — 닫기 X(`#9AA1AE`, 20px). 하단 1px `#EFF1F5`.
- **댓글 목록(스크롤)**: 시간 오름차순(과거→최신), 열릴 때 자동으로 맨 아래로 스크롤 [보강]. 각 댓글 =
  - 아바타 28px 이니셜(그룹장·관리자 포인트 톤 `#E0E7FF`/`#2F49B0`, 직원 중립 톤 `#EFF1F5`/`#3A4150`).
  - 메타 윗줄: 이름(13px 600) · **역할 태그 pill**(그룹장=검수대기/포인트 톤, 직원=회색 `#F1F2F4`/`#6B7280`, 관리자=별도 회색/포인트) · 시각(흐림 tnum). 본인은 이름 옆 "나" [보강].
  - 본문 아랫줄: 14px, line-height 21~22, `#3A4150`, keep-all, 줄바꿈 보존.
  - **그룹장 댓글**은 좌측 포인트 세로 라인 `inset 3px 0 0 #3B5BDB`로 "검수 측 코멘트" 강조 [보강]. 직원 댓글은 라인 없음.
  - 댓글 간 1px `#F2F3F6` 하단 보더 또는 12px 간격. 방금 단 댓글은 연한배경(`#EEF2FF`) 하이라이트 후 페이드 [보강].
- **컴포저(고정)**: 상단 1px `#EFF1F5`. textarea(보더 `#CBD0D9`, radius 8, padding 12, font 14, 세로 resize, placeholder "이 업무에 대한 댓글을 남겨주세요.", min-height ~56px, auto-grow 후 내부 스크롤 [보강]). **등록 버튼** 포인트 채움(`#3B5BDB`/흰글자, radius 8, 38~40px, 600), 입력 비면 비활성(흐림 톤). (선택) 본인 아바타/글자수.

### 상태
- **빈**: 목록 중앙 — 흐린 말풍선 + "아직 댓글이 없어요"(15px `#6B7280`) + "이 업무에 대한 첫 댓글을 남겨보세요."(13px `#9AA1AE`). 컴포저는 노출.
- **로딩**: 목록에 스피너 또는 스켈레톤 3줄(아바타 원 + 막대 2줄, `#EFF1F5`). 헤더·컴포저 즉시 표시.
- **등록 중**: 등록 버튼 내부 스피너 + 비활성. **등록 즉시 목록에 새 댓글이 보이고, 실패하면 해당 댓글이 에러 표시로 바뀐다**(화면 상태 전이로만 표현).
- **에러(로드)**: 목록에 경고 박스(bg `#FCEBEB`/border `#F5C2C2`/경고 아이콘 `#DC2626`) + "댓글을 불러오지 못했어요. 다시 시도".
- **에러(등록)**: 컴포저 위 인라인 1줄(`#DC2626` 13px 600) + 입력 유지.
- **열림/닫힘**: 닫기 = X / 오버레이 / ESC / (모바일) 아래로 드래그. 닫아도 본문 상태 유지.
- **읽기 전용(권한 없음)**: 컴포저 숨김 + 안내(또는 미렌더).

### 상호작용
1. 댓글 버튼 → 오버레이 + 드로어 → 목록 로드 → 최신으로 스크롤.
2. 입력 → 등록 활성 → 등록 → 새 댓글 맨 아래 추가 + 컴포저 비움 + 스크롤 다운 + **업무행 배지 +1 즉시 반영**.
3. 다른 업무행 댓글 버튼 → 헤더·목록을 해당 업무로 **내용 스왑** [보강].
4. (검수) 그룹장이 댓글로 가벼운 보완 요청 → 직원이 같은 업무행에서 응답. **댓글은 캐주얼 협의 채널, 반려 모달은 공식 채널**로 톤 구분.

### 역할별
- 공통: 진입 버튼·드로어·목록은 세 역할 모두 노출, 각 댓글에 역할 태그.
- 직원: 자기 보고서 업무행에서 열람·작성. 그룹장: 자기 그룹 검수 화면에서 열람·작성(자기 그룹 아니면 읽기 전용/미노출). 관리자: 열람 기본, 작성은 선택(미사용 시 컴포저 숨김 + "관리자는 열람만 가능합니다") [보강]. 본인 댓글은 "나" + (정책 허용 시) `⋯` 수정/삭제 [보강].

### 반응형
- PC: 우측 고정 드로어 400px. **1000px↓~720px 구간(태블릿)**: 드로어는 우측 고정 400px를 유지하되 화면이 좁으면 `min(400px, 92vw)`로 축소한다. 720px↓: 바텀시트로 전환.
- 진입 버튼은 PC `말풍선+숫자` 가로형, 모바일은 아이콘 + 우상단 숫자 배지로 축약(업무행 줄바꿈 방지).

# 기능 2 — 휴가/휴직/기타 선택 시 사유 입력 (최대 10,000자)

기존 **휴가 모드 카드**(작성 화면)를 확장한다. 유형에 **휴직**을 추가하고, **휴가류·휴직·기타** 선택 시 **사유 textarea**(최대 10,000자, 카운터/한도 처리)를 노출하며, 검수 화면에 그룹장/관리자용 **사유 읽기 카드**를 둔다.

**[기존→변경] (반드시 먼저 적용)**: 기존 휴가 모드 카드의 select 옵션은 `연차/반차/병가/공가/기타`이고, 입력 필드 라벨은 **'코멘트'**(필수 `*` 없음·비필수), placeholder "필요 시 사유나 인수인계 내용을 적어주세요.", **min-height 96**, **카운터 없음**이다. 이를 다음으로 바꾼다:
- 라벨 **'코멘트' → '사유'**로 교체.
- select 옵션에 **'휴직' 추가**(연차·반차·병가·공가·**휴직**·기타).
- 필수 유형(병가·휴직·기타)일 때 라벨에 **`*` 신설**, textarea 우하단에 **10,000자 카운터 신설**.
- textarea **min-height 96 → 160**으로 확대.

### 진입점
- **직원 작성 화면**: 기존 "오늘 휴가인가요? → 휴가로 전환" 프롬프트 → 시간대 섹션이 사라지고 **휴가 모드 카드** 한 장만 노출. 헤더 문구 "오늘은 휴가로 처리할까요? / 휴가 유형과 사유만 입력하면 됩니다." 카드 우상단 "← 업무 작성으로" 복귀 유지. 스테퍼는 회색 "휴가"(휴직/기타 동일 회색).
- **그룹장/관리자 검수 화면**: 휴가/휴직/기타 보고서를 좌측 본문에서 읽을 때 사유 읽기 카드 노출(읽기 전용). 우측 검수 액션바(승인/반려) 기존 그대로.

### 레이아웃 (휴가 모드 카드, 흰카드 + 1px `#E2E5EB` + radius 12 + 패딩 22px, 단일 컬럼)
순서: **유형 select → (휴가류·휴직·기타일 때만) 사유 라벨+필수/선택 안내 → 사유 textarea → 안내·카운터 한 줄(좌 안내/우 카운터)**.
- select 폭 `max-width:240px`, textarea 폭 100% · `min-height:160px`(기존 96에서 확대) · 세로 resize만 [보강]. 카운터/안내는 textarea 바로 아래 한 줄(좁으면 두 줄).

### 구성요소
- **유형 select**: 연차·반차·병가·공가·**휴직**·기타. 라벨 "유형 *"(`*`=`#DC2626`). 높이 44px, 보더 `#CBD0D9`, radius 8.
  - 사유 노출 규칙: **병가·휴직·기타 → 사유 textarea 펼침(필수)**, 연차·반차·공가 → 사유 "선택"(접거나 약한 안내) [보강].
- **사유 라벨 + 안내(유형별)**: 휴직 `사유 *` "휴직 사유와 기간·인수인계를 함께 적어주세요. (필수)" / 기타 `사유 *` "어떤 부재인지 사유를 적어주세요. (필수)" / 병가 `사유 *` "증빙이 필요하면 첨부와 함께 적어주세요." [보강] / 연차·반차·공가 `사유 (선택)` "필요 시 인수인계를 적어주세요. (선택)". 안내는 보조 톤(`#6B7280`, 12~13px), 필수 미입력 시 빨강 전환.
- **사유 textarea**: 유형별 placeholder 가변. 보더 `#CBD0D9`/radius 8/padding 12/font 14/세로 resize, 포커스 시 보더 `#3B5BDB` [보강]. 최대 10,000자.
- **글자수 카운터(신설)**: `1,234 / 10,000`(천단위 콤마, tnum), textarea 우하단, 기본 흐림 `#9AA1AE`.
- **ⓘ 승인자 표시 콜아웃**(필수 유형): 기존 야간 사유 콜아웃 그대로(글자 `#8A6508`/bg `#FBF4DA`/border `#EFE0A6`/radius 7) — "이 사유는 승인자(그룹장)에게도 함께 표시됩니다."
- **첨부(병가·휴직)** [보강]: 사유 아래 기존 점선 "＋ 파일 첨부" 패턴, 선택 항목.
- **하단 sticky 액션바**: 우측 `[임시저장]`(고스트) + `[휴가로 제출]`(휴가 회색 `#6B7280` 채움). 휴직 선택 시 라벨 "휴직으로 제출" 가변 [보강].
- **검수 읽기 카드(그룹장/관리자)**:
  - 요약 헤더 카드: 기존 휴가 변형 카드(가운데 정렬, 56px 원형 회색 `#F1F2F4`/`#6B7280` 안의 "/" 글리프)를 유형별 제목으로 치환한다. **기존 '휴가일입니다 (○○)' 문형을 그대로 따라** "휴직입니다", "기타 부재입니다 (예비군)"처럼 동일 문형으로 쓴다. 기간은 보조문. 하단 보조문도 기존 **"휴가 보고서도 관리자 확인이 필요합니다. 승인 또는 반려해 주세요."**를 재사용(유형명만 치환).
  - 사유 읽기 카드: 기존 "🌙 야간 업무 사유 / 작성자 제출" 콜아웃 카드 구조를 복제(좌선 3px `#B7860B`, bg `#FBF4DA`, border `#EFE0A6`). 헤더 "부재 사유" + pill "작성자 제출"(`#B7860B`). 본문은 사유 전문(줄바꿈 보존), 6~8줄 초과 시 "더 보기"로 펼침 [보강].
  - 위치: 좌 본문 최상단. 우측 AI 분석은 휴가 보고서에서 숨김(기존 동작과 일관).

### 상태
- 빈(필수·미입력): placeholder만, 카운터 `0 / 10,000`. 제출 시도/포커스 아웃 후 비면 안내·보더 빨강 + "사유를 입력해 주세요." 인라인 + 제출 비활성.
- 입력 중/정상: 카운터 흐림, 제출 활성.
- 한도 임박(≥9,000, 90%+): 카운터 주황 `#D97706`.
- 한도 도달/초과(10,000): **초과 입력은 차단되고 안내가 1회 뜬다**(붙여넣기로 초과해도 동일) — 카운터·보더 빨강 `#DC2626` + "최대 10,000자까지 입력할 수 있어요."
- 로딩(임시저장/제출): 버튼 스피너 + 비활성, 카드 살짝 흐림. 임시저장 후 "임시저장됨 · HH:MM" [보강].
- 에러(제출 실패): 액션바 좌측 빨강 인라인, 입력 보존.
- 유형 전환 토글: 사유 영역 펼침/접힘. 접힘 시 값 보존 후 복원 [보강](단 닫힌 사유는 제출 제외). **[보강] 사유가 입력된 상태에서 사유 불필요 유형으로 바꾸면 "입력한 사유는 제출에서 제외됩니다. 유지할까요?" 인라인 확인을 띄우고, 다시 필수 유형으로 되돌리면 값 복원**(임시저장된 사유가 있는데 비필수로 바꿔 제출하는 충돌 케이스 처리).
- 권한: 직원 편집 / 그룹장·관리자 읽기 전용(작성·수정 요소 미노출).

### 상호작용
휴가 전환 → 유형 선택 → (필수 유형) 사유 펼침 + 필수 안내 + ⓘ 콜아웃 → 입력(카운터 실시간, 90% 주황, 10,000 빨강·차단) → 필수 미입력 시 제출 비활성 → (선택) 첨부 → 임시저장/제출 → 제출 후 "검수 대기" 읽기 상태. 그룹장: 요약 카드 + 사유 읽기 카드 확인 → 승인/반려(휴가/휴직은 시간대 지목 대신 "사유 보완 요청" 톤으로 단순화 [보강]).

### 반응형
모바일: 카드 세로 스택, select 폭 100%, 안내/카운터 두 줄, textarea min-height 유지, 액션바 풀폭. 검수 우측 패널은 모바일 바텀시트/풀스크린, 사유 읽기 카드는 본문 상단.

# 기능 3 — 그룹장의 업무별 개별 반려 (직원이 마감한 업무)

검수 화면에서 그룹장이 **개별 업무(task) 단위**로 반려한다. 기존 "보고서 전체/시간대 반려"(액션바 반려 → 중앙 모달의 대상 지목 select)는 유지하고, **업무행 단위 반려**를 추가한다. 새 화면을 만들지 않고 기존 검수 2단 그리드(좌 본문 + 우 360px 사이드, 1000px↓ 1단) 위에 얹는다.

### 진입점
- **그룹장(검수, 자기 그룹)**: 좌 본문 시간대 섹션 안, **직원이 마감완료(✓)한 업무행 우측**에 `반려` 액션 노출(마감완료 업무에 한정).
  - PC: 행 우측 텍스트형 `반려` 버튼 — 기존 `마감` 버튼 형태(흰배경 + 컬러 외곽선 pill, 28px, radius 7)를 빨강(외곽선 `#F5C2C2`, 글자 `#DC2626 600`)으로 재사용.
  - 모바일/옵션: 행 우측 `⋯`(`#9AA1AE`) → 팝오버 `이 업무 반려`(빨강) / `취소`.
- **직원**: 자기 보고서 검수 화면은 읽기 전용. 진입은 목록 반려 배너 / 우측 "재작성하러 가기 →" / 작성 화면 상단 배너. **업무행 반려 액션·`⋯ 반려`는 미노출**.

### 개별 반려 입력 (인라인 펼침 / 바텀시트)
행 `반려` 클릭 시 **해당 업무행 바로 아래로 펼쳐지는 카드 안 카드**(배경 `#FBFCFD` 또는 연한 빨강, 보더 `#F5C2C2`, radius 10, 패딩 14).
- 헤더: "○○○ 업무 반려"(업무명 인용) + 닫기 ✕.
- 안내 배너: 노랑 톤(bg `#FBF4DA`/border `#EFE0A6`/글자 `#8A6508`) "이 업무만 반려됩니다. 작성자는 이 업무만 다시 작성·마감할 수 있어요."
- **자주 쓰는 사유 칩**(선택): 기존 모달 칩 재사용(흰배경 pill, 보더 `#E2E5EB`) — `근거 부족`, `시간 산정 재확인`, `결과물 첨부 필요`, `지연 사유 보완`.
- **그룹장 코멘트(필수 `*`)**: textarea(min-height 96, 보더 `#CBD0D9`, radius 8). 마이크로카피 "이 코멘트는 작성자의 보고서·재작성 화면에 그대로 표시됩니다."
- 푸터: `취소`(고스트) / `이 업무 반려`(코멘트 전 비활성 회색, 입력 후 활성 빨강 `#DC2626`/흰글자 — 기존 모달 활성/비활성 토글 패턴).
- 모바일: 동일 내용을 **풀스크린 바텀시트**로.
- **동시 오픈 금지 [보강]**: 인라인 반려 펼침이 열려 있는 동안 액션바 `[반려]`(전체/시간대 모달)는 **비활성** 또는 "열린 인라인 반려를 먼저 처리하세요" 안내로 막는다. 두 반려 UI 동시 오픈 금지.

### 반려된 업무행 표시 (그룹장·직원 공통)
- 상태 pill: `↩ 반려`(글자 `#DC2626`/bg `#FCEBEB`/border `#F5C2C2`), 기존 상태 pill 자리.
- 행 좌측 색 띠: `inset 3px 0 0 #DC2626`. **검수 본문 task 행에는 기존 `lineColor` 슬롯이 있으므로 그 슬롯을 재사용**한다. **[보강] 직원 작성 화면의 반려 행에는 기존 lineColor 슬롯이 없으므로 검수 행과 동일한 `inset 3px 0 0` 띠를 신규로 적용**한다.
- 반려 사유 줄: 기존 지연 사유 칩 패턴을 빨강 톤으로 — `반려 사유 · {코멘트}`(글자 `#B91C1C`/bg `#FCEBEB`/border `#F5C2C2`/radius 6). 업무명 아래.
- 반려자·시각 메타: `· 이정민 13:05`(흐림 `#9AA1AE`) [보강].

### 액션바 · 이력 · 직원 요약
- **액션바 요약**: 기존 `완결 7 · 지연 2 · 미완 1`에 **`· 반려 N건`**(빨강 `#DC2626 600`) 덧붙임(0건 미표시). 개별 반려가 있으면 `승인` 클릭 시 "반려 N건이 포함됩니다. 그대로 검수를 완료할까요?" 확인 팝오버 [보강] → 보고서는 **부분 반려 상태**로 회신.
- **검수 이력**(우 사이드, 기존 타임라인): 개별 반려 1건당 노드 — 점 빨강 `#DC2626`, 제목 "업무 반려", 부제 "13:05 · 이정민", 본문 "{업무명} · {코멘트 요약}".
- **직원 읽기 요약 카드**(우 사이드, 기존 빨강 반려 코멘트 카드 확장): 제목 "반려된 업무 N건" + 항목 반복(업무명 굵게 + 코멘트 + 시간대) + 하단 `재작성하러 가기 →`(포인트 `#3B5BDB`).

### 기존 전체/시간대 반려와의 공존
3단계 위계가 한 화면에서 공존한다: (1) 업무 단위(행 반려·인라인) (2) 시간대 지목(액션바 반려 → 모달 select 오전/오후/야간) (3) 전체(모달 select=전체 시간대).
- 규칙: 시간대 반려가 적용되면 **그 시간대 행들의 개별 반려 펼침·`반려` 액션을 숨기고 시간대 반려 배지로 대체**한다(모달 상단 "오후에 개별 반려 1건이 있어요. 시간대 반려에 포함됩니다." 안내). 더 넓은 범위가 반려 중이면 개별 `반려` 액션 숨김.
- **[보강] 기능 4(자동 분류) 적용 시 오전/오후는 사용자가 선택한 단위가 아니라 완료 시각으로 자동 분류된 결과**이므로, **시간대 지목 반려는 '해당 시간대 전체 재검토 요청'으로만 의미를 갖고, 특정 업무 보완은 업무 단위(행 단위) 반려를 우선 사용**한다. 모달 대상 지목 select 아래에 "특정 업무는 행 단위 반려를 사용하세요" 보조문을 둔다.

### 상태
- 빈: 마감완료 업무 없는 시간대엔 `반려` 액션 미노출. 개별 반려 0건이면 요약·이력·요약 카드 모두 미표시.
- 로딩: 확정 버튼 스피너 → 행 반려 상태 전환. 이미 반려된 행 액션은 `반려 취소`(고스트 `#CBD0D9`/`#6B7280`)로 토글 [보강].
- 에러: 코멘트 미입력 시 버튼 비활성 + textarea 아래 "반려 사유를 입력해 주세요"(`#DC2626`). 저장 실패 시 행 상단 빨강 인라인 경고.
- 권한: 그룹장(자기 그룹) 전부 노출 / 타 그룹·직원 기본 읽기. **관리자: 검수 화면 진입 시 기본 읽기 전용(행 반려·반려 취소 액션 미노출), 행 액션 영역에는 그룹장과 달리 댓글만 노출**(정책에 따라 달라질 수 있음은 [보강]로 남기되 기본 동작은 이 값으로 고정).
- 열림/닫힘: 인라인 펼침은 **한 번에 한 행만**(다른 행 열면 이전 닫힘), ✕·취소·바깥 클릭으로 닫힘.

### 상호작용
그룹장: 마감완료 행 `반려` → 인라인 펼침 → (칩 자동 채움) 코멘트 입력 → `이 업무 반려` → 행 `↩ 반려` 전환 + 빨강 띠·사유 줄 + 액션바·이력 갱신 → 잘못 시 `반려 취소`. 검수 종료 시 개별 반려 있으면 확인 팝오버 → 부분 반려 회신.

직원: 진입 → **작성 화면에서 반려된 그 업무행만 편집 가능**(파랑 좌측 띠 + 편집 활성). **기능 4 모델에는 섹션 자물쇠가 없으므로, 반려되지 않은 업무는 비활성(읽기) 처리하고, 반려된 업무행만 파랑 띠+편집 활성으로 강조한다(자물쇠 아이콘 미사용)**. 액션바 문구는 **기존 '반려된 시간대만 편집할 수 있어요'를 '반려된 업무만 편집할 수 있어요'로 교체**하되, 반려 범위가 시간대일 때는 '반려된 시간대만…'을 유지해 **반려 범위에 따라 문구를 분기**한다. → 보완 → `재제출` → 상태 `↻ 재제출`(`#2563EB`/bg `#E6EEFD`) + 이력에 노드.

### 반응형
PC: 행 우측 직접 `반려` 버튼 + 인라인 펼침, 우 사이드 360px sticky. 모바일: 행 액션은 `⋯` 우선, 반려 입력은 풀스크린 바텀시트, 액션바 요약 축약(`반려 N`), 좌·우 1단 스택.

# 기능 4 — 할 일 일괄 작성 + 완료 시각 기준 오전/오후 자동 분류

작성 화면의 **작성 모델을 전면 개편**한다. "시간대별로 나눠 작성"하던 모델을 폐기하고, **아침에 하루 할 일을 한 목록으로 일괄 작성** → 각 업무를 **마감할 때의 완료 시각**으로 **오전(≤11:59)/오후(≥12:00)에 자동 분류**한다. 검수·목록의 오전/오후 섹션 구조와는 호환.

### 변경 요약 (재사용/폐기 기준)
- 작성 단위: 시간대 섹션별 입력 → **단일 "오늘 할 일" 목록**.
- 시간대 섹션 카드: 입력 컨테이너 → **완료 업무가 자동으로 쌓이는 결과 컨테이너**(읽기 위주, 직접 추가 불가).
- 오전/오후: 사용자가 직접 선택 → **완료 시각으로 자동 결정**.
- 스테퍼: 계획→오전→오후→야간 4단계 → **작성 → 제출 2단계** + 오전/오후/야간은 분류 결과 미니 칩으로 강등.
- "＋ 업무 추가": 섹션마다 → **상단 "오늘 할 일"에 1개만**.
- 마감 시: 섹션 이동 없음 → **완료 시각 기록 + 오전/오후 섹션으로 자동 이동(슬라이드)** + **"마감 14:20" 완료 시각 칩** 신규 표시.
- 제거: 섹션 헤더의 "강제 마감"·"잠금 토글"(어떤 역할에도 미노출). **기능 4 화면에는 섹션 자물쇠/잠금 컴포넌트가 존재하지 않는다**(기능 3 직원 흐름과 연동: 자물쇠 대신 비활성 처리).
- **유지 재사용(외형 그대로)**: 페이지 헤더, 저장됨 표시, 알림 배너, 업무행(체크원·프로젝트칩·업무명·상태배지·계획대비실제·지연사유칩·⋯), 업무 추가 패널 폼, 휴가 모드, 야간 사유 입력, 하단 sticky 액션바, 스테퍼 노드 외형.

### 레이아웃 (중앙 1컬럼, max-width 808px / 본문 760px, 위→아래)
1. 페이지 헤더(제목 + 날짜 + "저장됨 · 오후 5:52" aria-live). 2. **2단계 스테퍼**. 3. 알림 배너(반려/어제 미완료/마감 임박, 조건부). 4. **[신규] "오늘 할 일" 작성 영역**. 5. **[자동] 완료 — 오전 섹션**. 6. **[자동] 완료 — 오후 섹션**. 7. **[조건부] 완료 — 야간 섹션**. 8. 커뮤니케이션 기록 + 일일 코멘트(기존). 9. 하단 sticky 액션바.
배치 원칙: **미완료(앞으로 할 일)는 위, 완료(이미 한 일)는 그 아래에 시간순**.

### 구성요소
- **"오늘 할 일" 작성 영역**(기존 "지금 할 일" 강조 카드 외형 계승 — 흰카드 + 좌측 3px `#3B5BDB`):
  - 헤더: pill "오늘 할 일"(`#EEF2FF`/`#3B5BDB`) + 우측 카운트 칩 "할 일 3 · 진행중 1"(`#6B7280`) [보강] + 마감 임박 시 "마감까지 1시간"(`#D97706`).
  - 타이틀 "오늘 할 일을 한 번에 적어두세요" / 서브 "각 업무를 마감하면 완료 시각에 따라 오전·오후로 자동 정리됩니다."(자동 분류 규칙 1줄 명시).
  - 미완료 업무 리스트(기존 업무행): 체크원(미완료=빈 원 `#CBD0D9`, 진행중=파란 점) · 프로젝트칩 · 업무명 · 상태배지(예정/진행중) · 계획정보("예정 14:00 · 2h") · 지연사유칩 · **[마감] 버튼**(핵심 액션) · `⋯`(수정/진행중표시/지연사유/삭제/야간으로 표시 [보강]).
  - **단일 "＋ 업무 추가"**(기존 점선 버튼) + 보조 칩 "↻ 어제 미완료 불러오기"·"반복 업무". 클릭 시 기존 업무 추가 패널(프로젝트명·최근 업무 추천·업무명·예정/소요 시간·첨부·URL)을 **이 영역 안에 인라인**으로 1개만 노출. 패널 하단 헬프 "여기 입력한 예정 시간은 계획이며, 오전/오후는 마감 시각으로 자동 결정됩니다."
- **완료 — 오전/오후 섹션**(기존 섹션 카드 외형, 단 좌측 강조 보더 없음 — 결과 영역. 섹션 헤더에서 입력·추가·잠금 버튼을 제거하고 읽기 결과 영역으로 렌더한다):
  - 헤더: 섹션명 "오전/오후" + 시간 범위 캡션("오전 00:00~11:59" / "오후 12:00~", `#9AA1AE` tnum) + 완료 개수 배지 "완결 N"(`#1F9254`/bg `#E7F6EC`, 지연 포함 시 "완결 3 · 지연 1"). 강제 마감·잠금 버튼 없음.
  - 완료 업무행(기존 업무행, 마감 버튼 없음): 상태배지 완결(✓)/지연(!) · **완료 시각 칩 "✓ 마감 09:40"**(회색 `#6B7280`/bg `#F1F2F4` 또는 무배경 tnum — 분류 근거임을 시각 연결) · detail "예정 2h · 실제 2h 10m" · 지연사유칩 · `⋯`(수정/마감 취소=다시 할 일로/야간으로 이동).
  - 내부 정렬 완료 시각 오름차순. 섹션에 "＋ 업무 추가" 없음.
- **2단계 스테퍼**(기존 노드+연결선+라벨+캡션 외형 재사용): 노드1 "작성"(진행 중 파란 활성, 캡션 "할 일 4 · 완료 1"), 노드2 "제출"(미제출 흐림 `#CBD0D9`/`#9AA1AE`, 제출 후 완결색 `#1F9254` 채움 + 캡션 "오후 6:10 제출"). 연결선 진행도 채움.
  - **[보강] 기존 스테퍼의 양방향 라인 슬롯(`lineLeft`/`lineRight`)을 유지하되, 첫 노드 왼쪽·끝 노드 오른쪽 라인은 투명(배경색) 처리**해 2노드에서도 동일 컴포넌트로 렌더되게 한다. 두 노드 사이 라인만 진행도 색으로 채운다.
  - 보조 분류 미니 칩 [보강]: 스테퍼 아래/우측에 "오전 2 · 오후 1 · 야간 0"(회색) — 시간대는 단계가 아니라 **분류 바구니**임을 명시. 야간 칩은 야간 토글/업무 있을 때만.

### 자동 분류 UI 반영
- 규칙 고지: "오늘 할 일" 서브텍스트 + 추가 패널 헬프에 "완료 11:59 이전 → 오전 / 12:00 이후 → 오후" 상시 노출.
- 마감 순간 피드백 [보강]: 짧은 토스트/인라인 "오전으로 분류됨 · 마감 09:40"(완결색) + 해당 행이 "오늘 할 일"에서 사라지고 해당 섹션 시간순 위치로 **부드럽게 슬라이드 이동**.
- 경계 인지: 오전 "~11:59" / 오후 "12:00~" 캡션 상시(상한 표기 없이 오후는 "12:00~"). 완료 시각 ⋯ 수정으로 경계 넘으면 오전↔오후 자동 재이동 + "오후로 재분류됨" 안내.

### 미완료 업무 처리
- 미완료(예정·진행중)는 절대 섹션으로 내려가지 않고 항상 "오늘 할 일" 상단에 머문다. 내부 정렬 진행중→예정, 예정 시작 시각 오름차순 [보강].
- 제출 시 미완료 남으면: 제출 컨펌에서 "미완료 N건이 있습니다. 이대로 제출하면 미완 상태로 보고됩니다." 경고(`#FDF3E5`/`#D97706`). 미완료는 "미완" 상태로 보고서에 별도 "미완료" 묶음 포함(검수의 "미완 1" 집계와 연결, 검수 본문에도 회색 "미완료" 섹션 [보강]). 선택지: 이대로 제출 / 내일로 이월 [보강] / 취소.

### 제출(마감) 흐름
하단 sticky 액션바(기존 외형) — 좌측 보조 텍스트 + `임시저장` + 주 버튼(라벨 "제출하기"→"제출 완료"(비활성/완결색)→"다시 제출"). 제출 시 요약 컨펌(바텀시트/모달): "완결 X · 지연 Y · 미완 Z" + 분류 미리보기 미니 칩 + 미완 경고. 제출 후 스테퍼 노드2 채움 + 화면 읽기 전용 잠금. 임시저장은 완료/미완료 상태 그대로 보존.

### 야간 처리
야간은 오후 규칙과 충돌하므로 **명시적 플래그**. 야간 토글(기존 컴포넌트) "없음/있음" + "있음" 시 야간 사유 textarea(필수) + "승인자에게도 표시됩니다" 안내(`#FBF4DA`). 야간 분류는 **사용자 지정 우선**(⋯ "야간으로 표시"한 업무만 야간 섹션으로) [보강]. 야간 섹션은 오전/오후와 동일 외형 + 헤더 🌙 + 야간 사유 요약. 미니 칩 "야간 N"도 이때만.
- **[보강] 경계 처리**: 18:00 이후 마감이라도 **야간 플래그가 없으면 오후로 분류**한다. 오후 캡션은 상한 표기를 제거하고 "오후 12:00~"으로 두어 빈 구간이 생기지 않게 한다. 야간 섹션에는 플래그된 업무만 들어간다.

### 상태
- 빈(아침 최초): 오전/오후 섹션은 점선/연한 플레이스홀더 "오전 · 완료된 업무가 여기에 쌓입니다"·"오후 · 12:00 이후 완료 업무가 정리됩니다"(흐림 `#9AA1AE`). "오늘 할 일" 비면 큰 "＋ 첫 업무 추가" CTA + "어제 미완료 불러오기".
- 로딩: 불러오기 스켈레톤, 저장 중 헤더 스피너.
- 에러: 저장 실패 상단 배너(`#FCEBEB`/`#DC2626`) + 재시도, 마감 실패 행 인라인 에러.
- 마감/이동 중: 마감 버튼 스피너 → 이동 모션. **[보강] 이동(자동분류) 실패 시 행은 "오늘 할 일"에 남고 인라인 에러 "분류에 실패했어요. 다시 시도"를 표시**한다.
- 제출 후(닫힘): 추가/마감 비활성(흐림), 섹션 읽기 전용, 액션바 잠금.
- 반려 후(부분 열림): 반려 배너(`#FCEBEB`) + 그룹장 코멘트. **섹션 잠금/자물쇠가 아니라(기능 4에는 자물쇠가 없음), 반려되지 않은 업무는 비활성(읽기) 처리하고 반려된 업무행만 파랑 띠+편집 활성으로 강조**(기능 3과 일치) + 재마감/수정 가능. 액션바 문구는 반려 범위에 따라 "반려된 업무만 편집할 수 있어요"/"반려된 시간대만 편집할 수 있어요"로 분기하고 "반려 사유를 반영해 다시 제출해 주세요"를 함께 둔다.
- 휴가(열림/닫힘): "휴가로 전환" → 휴가 모드 카드로 본문 교체(기능 2와 동일), "← 업무 작성으로" 복귀.

### 역할별
직원: 전체 사용(추가·마감·제출·야간·휴가, 분류 결과 확인). 그룹장: 작성은 직원과 동일, **검수 화면에서 결과 읽기 + 완료 시각 칩 추가 표시**(분류 타당성 확인), 자기 그룹만. 관리자: 작성 미사용, 목록/통계 집계만(분류 규칙은 정책 설정 대상이면 관리 화면, 본 스펙 범위 밖 [보강]).

### 반응형
PC: 1컬럼 808px, 스테퍼 가로 스크롤 허용, 업무행 한 줄. 모바일: 마감 버튼 행 우측 고정·완료 시각/계획정보 줄바꿈, 추가 패널·제출 컨펌 바텀시트/풀스크린, 섹션 시간 범위 캡션 유지, 2노드 스테퍼 한 줄 유지·미니 칩 줄바꿈.

# 공통 지침 (4개 기능 전체 적용)

- **상태 처리**: 모든 신규 영역은 **빈 / 로딩 / 에러 / 권한별 / 열림·닫힘** 상태를 빠짐없이 디자인한다. 로딩=스피너 또는 스켈레톤(`#EFF1F5` 톤), 에러=빨강 톤 박스(bg `#FCEBEB`/border `#F5C2C2`/아이콘 `#DC2626`) + "다시 시도", 빈=흐린 아이콘 + 안내 문구 + (가능 시) 바로 작성 유도. 입력 미충족 버튼은 비활성 흐림 톤으로 일관.
- **접근성**: 저장/실시간 변경은 aria-live("저장됨"). 모달/드로어/시트는 ESC·바깥 클릭·X로 닫고 포커스 트랩·열릴 때 포커스 이동, 닫으면 트리거로 복귀. 모든 인터랙티브 요소에 포커스 링(`0 0 0 3px rgba(59,91,219,.35)`). 상태는 색만으로 구분하지 않고 **아이콘 + 라벨**을 함께(상태배지 규칙). 터치 타깃 충분히. 한국어 라벨·문구 일관.
- **일관성**: 새 색·새 폰트·새 컴포넌트 금지 — 위 토큰/컴포넌트만 재사용·재해석한다. 카드/경계/그림자/라운드, 상태색 짝(글자·bg·border), 아바타 톤, 버튼 위계(포인트 채움/고스트/비활성), 역할 pill, 커스텀 스크롤바·스피너, sticky 액션바, 모달/드로어/바텀시트 패턴을 모든 기능에서 동일하게 적용한다. 숫자·시각은 tnum, 본문은 keep-all. **PC 기본 + 720px 모바일** 반응형은 `.pc-only`/`.sm-only` 규칙과 "모바일에서 모달/사이드 패널 = 풀스크린/바텀시트" 원칙을 그대로 따른다. **z-index·sticky는 절대 수치 단정 금지 — 각 화면의 기존 sticky 헤더 높이 기준, 새 오버레이/드로어/시트는 기존 반려 모달(200) 위로 쌓는다.**

(참조: 기존 마크업 `/Users/whatsupjuno/WTF/dailyReport_seeding/_design_decoded.html` — 작성 업무행/추가 패널·휴가 모드·야간 사유·작성 액션바·스테퍼, 검수 업무행·반려 모달·검수 이력·직원 반려 패널·검수 액션바의 토큰을 그대로 사용. 기존 lineColor 슬롯은 검수 본문 행에만 존재, 휴가 모드 입력 필드 라벨은 '코멘트'(비필수·min-height 96·카운터 없음)임에 유의.)

# 부록 — 기능별 적용 위치 (기존 HTML 마크업 기준)

> 각 기능이 **기존 디자인의 어느 화면·어느 요소**에 붙는지. 줄 번호는 디코딩 마크업 `_design_decoded.html` 기준이며, 인용한 `<div>`/`<button>` 태그가 그 자리(앵커)다. Claude Design은 새 HTML을 그리되 **이 위치/요소에 대응**하도록 한다.

## 기능 1 — 업무별 댓글 → 작성·검수 화면의 **업무행**

- **작성 화면 · 업무행**: 시간대 섹션 카드 안의 업무 한 줄.
  - 섹션 카드(345): `<div style="background: #fff; border: 1px solid {{ sec.cardBorder }}; border-left-width: {{ sec.activeLeft }}; ...">`
  - 업무행(361): `<div style="display: flex; align-items: flex-start; gap: 10px; padding: 12px 0; border-bottom: 1px solid #F2F3F6;">`
  - 댓글 버튼은 이 행 우측의 **`마감` 버튼(372 `onclick="{{ onCloseTask }}"`)과 `⋯` 버튼(373 `<button …>⋯</button>`) 사이**에 삽입. (완료 행은 `마감`이 없으므로 `[댓글]→[⋯]`)
- **검수 화면 · 업무행(읽기)**: 오전 `<sc-for list="{{ reviewMorningTasks }}">`(727) / 오후 `<sc-for list="{{ reviewAfternoonTasks }}">`(743).
  - 업무행(728/744): `<div style="… box-shadow: inset 3px 0 0 {{ tk.lineColor }};">` — 행 우측에 댓글 버튼 단독.
- **드로어 본체**는 신규 우측 오버레이. z-index는 기존 반려 모달(826 `z-index: 200`) **위**.

## 기능 2 — 휴가/휴직/기타 사유 → 작성 화면 **휴가 모드 카드** + 검수 **휴가 변형 카드**

- **작성 화면 · 휴가 모드**: `<sc-if value="{{ isVacationMode }}">`(327).
  - 카드(328): `<div style="background: #fff; border: 1px solid #E2E5EB; border-radius: 12px; padding: 22px; …">`
  - 유형 select(334) `<option>연차</option>…<option>기타</option>` → **`휴직` 추가**.
  - 라벨 "코멘트"(337) + textarea(338, `min-height: 96px`) → **라벨 "사유" + 10,000자 카운터 + min-height 160**으로 교체.
- **검수 화면 · 휴가 변형 카드**: `<sc-if value="{{ reviewIsVacation }}">`(708), 카드(709) `<div style="… padding: 40px 24px; text-align: center;">` → 그 아래 **사유 읽기 카드** 추가(기존 야간 사유 콜아웃 구조 재사용).

## 기능 3 — 업무별 개별 반려 → 검수 **업무행** + 액션바/반려 모달 + 직원 작성 액션바

- **검수 화면 · 업무행**(728/744): 마감된 업무행 우측에 **행 단위 "반려" 액션** 신규.
- **검수 액션바/반려 모달**: 액션바(814), `<button onclick="{{ onReject }}">반려</button>`(818), 모달(826~), **"대상 지목" select(842)**. → 시간대 지목 반려와 **공존**(특정 업무는 행 단위 반려 우선, 모달에 보조문).
- **직원 작성 액션바**: `<sc-if value="{{ writeRejected }}">…반려된 시간대만 편집할 수 있어요.`(507) → 반려 범위에 따라 **"반려된 업무만"**으로 분기.

## 기능 4 — 일괄 작성 + 완료시각 오전/오후 분류 → **스테퍼 + 시간대 섹션 스택 + 지금 할 일 헤더**

- **하루 진행 스테퍼**(267~282): 컨테이너(268) `<div style="… overflow-x: auto;">`, `<sc-for list="{{ stepper }}">`(270) → **4노드(계획·오전·오후·야간) → 2노드(오전·오후)**. 첫 노드 왼쪽/끝 노드 오른쪽 라인 투명.
- **시간대 섹션 스택**: `<sc-if value="{{ showSections }}">`(342), `<sc-for list="{{ sections }}">`(344), 섹션 카드(345). → **"입력 컨테이너"에서 "완료 업무가 쌓이는 결과 바구니(오전/오후)"로 성격 변경.** 강제 마감 버튼(351 `onclick="{{ onForceClose }}"`)·잠금 토글은 **제거**.
- **지금 할 일 헤더**(288) + **업무 추가 폼**(378 `＋ 업무 추가`, `onToggleAdd`) → 상단 단일 **"오늘 할 일" 일괄 작성 영역**으로 통합(완료 시각 11:59 이전→오전 / 12:00~→오후로 자동 이동).
