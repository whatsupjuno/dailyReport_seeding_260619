# Seeding 디자인 v2 검증 종합 리포트

## 1. 한 줄 결론

기능 1·2·4는 핵심 요구를 대체로 반영했으나 상태/모션/안내 디테일에 누락이 있고, **기능 3(개별 반려)은 직원 작성화면의 task 단위 편집 모델이 섹션 단위로 구현되어 핵심 요구가 빠진 부분반영** 상태다. 따라서 전체 요구사항이 모두 반영되었다고 볼 수 없으며, 구현 전 보완이 필요하다.

## 2. 기능별 요약 표

| 기능 | 반영 정도 | 핵심 근거 |
|---|---|---|
| 1 — 업무별 댓글(우측 드로어) | 대체로 반영 | 진입 버튼·헤더·목록·컴포저·안읽음 강조는 충족. 슬라이드-인 모션 부재, 상태 디자인(로딩/등록중/에러)이 빈 상태만 구현, ESC·모바일 드래그·권한별 컴포저 제어 누락 |
| 2 — 휴가/휴직/기타 사유 입력(10,000자) | 대체로 반영 | '휴직' 옵션·카운터·승인자 콜아웃·textarea 높이는 충족. 필수 표기가 별표(*) 대신 회색 '(필수)', 한도 초과 1회 안내·보더 빨강 누락, 유형별 펼침/접힘 미구현, 검수 읽기 카드가 '휴직' 단일 하드코딩 |
| 3 — 그룹장 업무별 개별 반려 | **부분 반영** | 검수 행 반려 버튼·인라인 카드·반려 배지/메타/빨강 띠는 충족. **직원 작성화면이 task 단위가 아닌 섹션 단위 편집(핵심 요구 미구현)**, 권한이 역할이 아닌 검수 variant 기반, 부분반려 확인 팝오버·모달 보조문·동시오픈 금지 누락 |
| 4 — 일괄작성+완료시각 오전/오후 자동분류 | 대체로 반영 | 단일 일괄 입력·완료시각 분류·경계(11:59/12:00)·결과 바구니·2노드 스테퍼·강제마감 제거는 충족. ⋯ 시각 수정→재분류 인터랙션 전체 누락, 마감 슬라이드 모션 부재, '내일로 이월' 선택지·'마감까지 1시간' 인디케이터·아침 첫 업무 CTA 누락 |

## 3. 보완 필요 (누락·부분·이탈 항목)

### 기능 3 — 우선순위 높음 (핵심 요구 이탈)
- **[누락] 직원 작성화면 task 단위 편집 모델**: 요구는 '반려된 업무행만 파랑 띠+편집 활성, 나머지 비활성'이나, 구현은 섹션 단위 편집(`resultSections editable=wMode!=='view'`, 1914행)이라 오전·오후 전체 행에 '마감 취소'가 노출됨. `mapDoneRow`(1387~1398)에 rejected 플래그·파랑 띠·행별 편집 슬롯 없음.
- **[부분] 권한 모델**: 행 반려 게이팅이 역할이 아닌 검수 variant 기반(`reviewIsLeader = rv==='pending'||'resubmitted'`, 2048행). '그룹장만' 역할 권한과 '관리자=읽기·댓글만' 분기 미표현.
- **[누락] 부분반려 확인 팝오버**: 검수 종료 시 '반려 N건이 포함됩니다…' 확인 없이 `onApprove`가 즉시 approved 전환(1685행).
- **[부분] 모달 공존 안내**: 보조문 '특정 업무는 행 단위 반려를 사용하세요', 시간대-개별 반려 포함 안내/숨김 규칙 누락. 동시 오픈 금지는 `inlineRejectOpen`만 계산되고 액션바 버튼 disabled로 미연결(2064/892행).
- **[부분] 액션바 카피 분기**: '반려된 업무만 편집'이 하드코딩(539행), '반려된 시간대만…' 범위 분기 및 '반려 사유를 반영해 다시 제출' 동반 안내 없음.
- **[누락] 직원 우측 요약 카드 확장**: '반려된 업무 N건' + 항목 반복(업무명·코멘트·시간대) 미구현(단일 코멘트 카드만).
- **[누락] 검수 이력 노드 동적 생성**: 개별 반려 건당 노드가 정적 1건('반려 13:05 · 이정민')만 존재, taskRejects 기반 아님.
- **[누락] 모바일 변형**: 행 반려 입력 풀스크린 바텀시트, 행 우측 ⋯→'이 업무 반려' 팝오버 미구현.

### 기능 1
- **[부분] 슬라이드-인 모션**: `sc-if` 즉시 토글로 등장/소멸, translateX .2s ease 모션 부재. '열릴 때 맨 아래 자동 스크롤', '방금 단 댓글 하이라이트 후 페이드'도 미구현(`fresh` 플래그만 세팅·미사용).
- **[부분] 상태 디자인**: 빈 상태만 구현. 로딩(스켈레톤/스피너)·등록 중(버튼 스피너+비활성)·로드 에러(경고박스+다시 시도)·등록 에러(인라인 빨강) 전부 부재.
- **[누락] 권한별 컴포저 제어**: 읽기 전용 시 컴포저 숨김, '관리자는 열람만' 안내, 본인 댓글 ⋯ 수정/삭제 없음.
- **[부분] 닫기/접근성**: ESC 키 핸들러·모바일 드래그 닫기·포커스 트랩 미구현(X·오버레이만). 등록 버튼 `disabled` 속성 미바인딩(시각 흐림만).
- **[부분] 모바일**: 드래그 핸들·풀스크린 확장·키보드 회피 처리 없음.
- **[이탈] 완료행 액션 순서**: 기능4 '마감 취소'가 댓글 앞에 와 [마감취소]→[댓글]→[⋯]가 됨. 순수 [댓글]→[⋯]는 `sec.editable=false`일 때만 성립.

### 기능 2
- **[부분] 필수(*) 표기 형식**: 별표(*) 대신 회색 '(필수)/(선택)' 텍스트. 같은 화면 유형 select·야간 사유는 #DC2626 별표를 쓰는데 사유 라벨만 불일치.
- **[부분] 한도 초과 처리**: '최대 10,000자까지 입력할 수 있어요' 1회 안내·보더 빨강 누락. `onVacReason`이 안내 없이 slice로 무음 차단(1456행).
- **[부분] 유형별 펼침/접힘**: textarea가 모든 유형에서 항상 노출. 연차·반차·공가에서 '접거나 약한 안내', '사유 불필요 유형 전환 시 제출 제외 확인' 없음.
- **[누락] 빈/제출 시도 안내**: '사유를 입력해 주세요' 인라인 빨강·보더 빨강 없음.
- **[부분] 검수 읽기 카드**: '휴직' 단일 변형 하드코딩(743·744·750행). 기타/병가 등 유형별 제목 치환, 6~8줄 초과 '더 보기' 펼침 미반영.

### 기능 4
- **[누락] ⋯ 시각 수정→경계 재분류**: ⋯ 버튼(348/458행)이 onclick 없는 정적 버튼, 시각 수정 UI 및 '오후로 재분류됨' 인터랙션 전체 부재.
- **[부분] 마감 피드백**: 토스트는 구현, 행 '부드러운 슬라이드 이동' 모션 없음(즉시 재렌더).
- **[누락] '내일로 이월' 선택지**: 제출 컨펌이 '취소/제출하기' 2개뿐.
- **[누락] '마감까지 1시간' 인디케이터**: 헤더 마감 임박 표시 없음.
- **[부분] 빈(아침 최초) 상태**: 큰 '＋ 첫 업무 추가' CTA·'어제 미완료 불러오기' 없음. todoEmpty가 '모두 마감했습니다 👍'(완료 후 문구)로만 처리.
- **[부분] 반려 모드 시각 차등**: 작성 todoTasks 행에 '반려행만 파랑 띠+편집 활성, 그 외 비활성' 미반영(기능 3과 동일 원인).
- **[부분] 자동분류 고지 문구**: '11:59 이전/12:00 이후' 숫자가 캡션에만 있고 서브텍스트/헬프에는 없음.
- **[미세 편차]** 스테퍼 제출노드 미제출 배경 #F1F2F4(지시문 #CBD0D9).
- **[데모 한계]** 추가 패널 '추가' 버튼이 `onCancelAdd`에 연결(403행)되어 실제 추가가 아닌 패널 닫기로 동작.

## 4. 구현 단계 유의점

1. **기능 3의 편집 모델을 섹션 단위 → task 단위로 재설계**가 최우선이다. 현재 `resultSections editable` / `mapDoneRow` 구조에 행별 `rejected` 플래그·파랑 띠·편집 활성 슬롯이 없어, 마크업뿐 아니라 상태/분류 로직(1387~1398, 1914행)까지 손대야 한다. 디자인 단계에서 task 단위 데이터 모델과 행 템플릿을 먼저 확정해야 구현 재작업을 막을 수 있다.

2. **권한을 역할(role) 기반으로 일원화**해야 한다. 현재 반려 노출이 검수 variant(`pending`/`resubmitted`)에 묶여 있어 '그룹장만 반려 / 관리자=읽기·댓글만 / 직원·타그룹=읽기'를 표현하지 못한다. 검수·댓글·작성 전반에 걸친 역할 게이트를 공통 로직으로 두고, 기능 1의 컴포저 숨김/안내도 여기에 연결할 것.

3. **상태·모션·1회 안내류는 공통 패턴으로 묶어 일괄 보강**하라. 슬라이드-인(드로어/마감 행 이동), 로딩·등록중·에러 상태, 한도 초과/빈 입력 인라인 안내가 기능별로 산발적으로 빠져 있다. 개별 대응보다 재사용 가능한 상태/트랜지션/인라인 경고 컴포넌트를 먼저 만들고 각 기능에 적용하는 편이 누락을 줄인다.
