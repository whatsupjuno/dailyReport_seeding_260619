## 2. 제품 개요

직원이 **일일 업무 보고서**를 작성·제출하고, 그룹장이 **검수(승인/반려)** 하며, 관리자가 **사용자·그룹**을 관리하는 사내 웹 애플리케이션입니다.

핵심 도메인 개념:
- **업무(task)**: 하루의 단위 업무. 작성자가 "오늘 할 일"로 적고, **마감(완료) 시 완료 시각으로 오전/오후 자동 분류**됩니다(오전/오후는 "단계"가 아니라 완료 시각 분류).
- **보고서(report)**: 하루치 업무 묶음 + 커뮤니케이션 기록 + 일일 코멘트. 제출 → 검수대기 → 승인/반려.
- **역할(role)**: `직원 / 그룹장 / 관리자`. 모든 권한은 역할 기반으로 일원화되어 있습니다.
- **부분 반려**: 그룹장은 보고서 전체가 아니라 **개별 업무행 단위로 반려**할 수 있습니다.

## 3. 역할(Role) & 권한 모델  ★중요

세 가지 역할이 있고, 화면 노출·동작이 역할로 결정됩니다. (프로토타입에서는 상단 헤더의 "역할 전환 · 데모" 세그먼트로 전환 — **실제 제품에는 이 토글이 없고**, 로그인 사용자의 역할로 결정됩니다.)

| 역할 | 데모 프로필 | 목록 화면 | 검수 화면 | 댓글 작성 |
|---|---|---|---|---|
| **직원** | 김도윤 · 개발팀 | "내 보고서"(본인 것만) | 읽기 전용 + 반려 시 "재작성하러 가기" | 가능 |
| **그룹장** | 이정민 · 마케팅팀 | "팀 보고 현황"(통계 4카드 + 팀원 표) | **승인/반려 + 행 단위 반려** 가능 | 가능 |
| **관리자** | 박소라 · 운영 | "팀 보고 현황" | **열람 전용**("관리자는 열람만…" 안내, 액션바·반려버튼 숨김) | 불가(열람만) |

권한 게이트 규칙:
- `isManager = role ∈ {그룹장, 관리자}` → 목록의 매니저 뷰(통계+직원 컬럼) 노출.
- `reviewIsLeader = role == 그룹장` → 검수 화면 행 반려 버튼 + 하단 승인/반려 액션바 노출.
- `isEmployeeRead = role == 직원` → 검수 화면 우측 "그룹장 반려 코멘트 + 재작성" 카드 노출.
- 관리자 = 검수 열람 전용(액션 불가), 댓글 작성 불가.

## 4. 화면 구성 (Screens / Views)

앱은 **로그인 → 앱 셸(상단바 + 좌측 LNB) → 4개 메인 화면**(작성/목록/검수/관리)으로 구성됩니다.

### 4.0 앱 셸 (공통 크롬)
- **상단바**: 높이 56px, 흰 배경, 하단 1px `#E2E5EB` 보더, `position: sticky; top:0; z-index:50`.
  - 좌: 로고(28px 라운드 8px `#3B5BDB` 사각 + 흰 햄버거 아이콘) + "Seeding"(16px/700).
  - (데모 전용) 역할 전환 세그먼트 — 프로덕션 제외.
  - 우: 프로필 버튼(아바타 26px 원 `#E0E7FF`/`#2F49B0` + "이름 · 부서") + 로그아웃 버튼(높이 34px, 1px `#CBD0D9` 보더, 라운드 8px).
- **좌측 LNB**(PC, 폭 220px, 흰 배경, 우측 1px 보더): 작성/목록/검수/관리 4개 항목(아이콘 17px + 라벨 14px/600, 활성 시 배경 `#EEF2FF`/글자 `#2F49B0`, 라운드 8px). 하단에 화면별 서브내비(섹션 라벨 11px/700 대문자 + 칩 목록).
- **모바일**(≤720px): 좌측 LNB 숨김 → 상단 가로 스크롤 탭(필 버튼) 2줄(메인 탭 + 서브 변형). **(아래 9. 반응형의 셸 레이아웃 주의사항 필독)**

### 4.1 로그인 (`screen = login`)
- 중앙 정렬 카드(최대 400px, 흰 배경, 라운드 16px, 그림자 `0 1px 3px rgba(16,24,40,.08)`, 패딩 32px).
- 구성: 로고+서브타이틀("What The Hell Are You Doing?") → "로그인" 제목(28px/700) → 안내문(14px `#6B7280`).
- **메일 링크 배너**(선택): `#EEF2FF` 배경 + 좌측 3px `#3B5BDB` 보더 + 정보아이콘, "로그인하면 6월 18일 업무 보고서로 바로 이동합니다."
- **아이디 입력**(라벨 + 빨강 `*` 필수): 높이 48px, 1px `#CBD0D9`, 라운드 8px. 포커스 시 보더 `#3B5BDB` + 링 `0 0 0 3px rgba(59,91,219,.35)`.
- **인증번호 OTP 4칸**: 각 칸 높이 56px, 가운데 정렬 22px/700, `tabular-nums`. 입력 시 자동 다음 칸 포커스, 붙여넣기 시 4자리 분배, Backspace 시 이전 칸. 채워지면 보더 `#3B5BDB`.
- **에러 상태**: 빨강 경고 박스(`#FCEBEB`/`#F5C2C2`/`#DC2626`), `role="alert" aria-live="assertive"`.
  - 검증: 아이디 `unknown.user` → "존재하지 않는 아이디"; 인증번호 ≠ `7391` → "인증번호 불일치"(OTP 리셋); 미입력 → "모두 입력".
  - 데모 정답: 아이디 `kim.minji`(임의), 인증번호 `7391`.
- **로그인 버튼**: 높이 48px, 입력 완료 전 비활성(`#E2E5EB`/`#9AA1AE`), 완료 시 `#3B5BDB`/흰색. 로딩 시 스피너(0.7s linear) + "로그인 중…" (700ms 후 작성화면 이동).

### 4.2 작성 (`screen = write`) — 직원 핵심 화면
페이지 폭: 헤더/액션바 max 808px, 본문 카드 max 760px, 가운데 정렬.

**작성 모드(writeMode)**: `work`(작성) / `view`(제출본·읽기전용) / `rejected`(반려·재작성) / `vacation`(근태). 데모 LNB 서브내비로 전환.

#### 페이지 헤더 (흰 배경, 하단 보더, 패딩 14/24)
"일일 업무 보고서" 17px/700 + 날짜 "2026년 6월 18일 (목)" + **"마감까지 1시간" 임박 칩**(work/rejected 시; 앰버 `#FDF3E5`/`#F6D9A8`/`#B45309`, 시계 아이콘) + "저장됨 · 오후 5:52"(녹색 체크).

#### 알림 배너 (모드별)
- rejected: 빨강 배너 "그룹장이 보고서를 반려했습니다. 반려된 업무 N건만 수정·재마감하면 됩니다." + 코멘트.
- view: 골드 배너 "제출 완료 · 검수 대기 중".

#### "오늘 할 일" 카드 (work/rejected)
- 흰 카드, 좌측 3px `#3B5BDB` 강조 보더, 라운드 12px.
- 헤더: "오늘 할 일" 칩(`#EEF2FF`/`#3B5BDB`) + 개수 라벨 + **"근태 변경" 버튼**(우측, 1px `#CBD0D9` 라운드 8px) → vacation 모드 진입.
- 안내문: "오늘 할 일을 한 번에 적어두세요 / 각 업무를 마감하면 완료 시각에 따라 오전·오후로 자동 정리됩니다."
- **미완료 업무 리스트**(각 행):
  - 좌측 체크 원(20px, 진행중이면 파란 점) + 프로젝트 칩(선택) + 업무명(14px/600) + 상태 배지 + 🌙야간 배지(선택) + 예정시간(11px 회색).
  - 우측 액션: **[마감]**(파랑 버튼) · **[댓글]**(보더 버튼 + 미읽음 시 파란 N 필) · **[⋯]**(더보기 메뉴).
  - **마감 버튼** 클릭 → 완료 시각(`nextCloseTime`, 데모 15:10부터 25분씩 증가) 부여, 12시 기준 오전/오후 자동 분류, 토스트 "오전/오후로 분류됨 · 마감 HH:MM".
  - **⋯ 더보기 메뉴**(고정 위치 드롭다운, 백드롭 클릭/ESC로 닫힘): **수정**(수정 모달) / **✓마감 또는 ↩마감 취소** / **🗑삭제**(삭제 확인 모달). ⋯ 버튼은 행 기준 **세로 가운데** 정렬.
- **업무 추가**: 닫힘 시 "＋ 업무 추가"(점선 보더 풀폭) + "↻ 어제 미완료 불러오기"·"반복 업무" 칩. 열림 시 인라인 폼:
  - 프로젝트명(선택, 입력 시 "최근 진행한 업무" 자동완성 드롭다운 — 프로젝트별 RECENT 데이터) + 프로젝트 칩.
  - 업무명(필수 `*`) + 예정 시간/소요 시간 셀렉트(선택).
  - 취소 / **추가**(업무명 있어야 활성). 추가 시 새 업무를 "오늘 할 일"에 추가하고 토스트.
- **야간 업무 독립 토글**: "야간 업무가 있나요?" 없음/있음 세그먼트(오전·오후와 무관). "있음" 시 **야간 사유 textarea**(필수) + "이 사유는 승인자(그룹장)에게도 표시됩니다" 골드 콜아웃.

#### 완료 결과 바구니 (오전 / 오후 / 야간)
- 각 섹션 카드(흰, 라운드 12px): 헤더("오전" + 시간범위 + 완결/지연 카운트 배지), 본문은 마감된 업무 행(좌측 체크 원: 완결=녹색✓, 지연=빨강!).
- 행 우측: 편집 가능 시 **[마감 취소]**(또는 rejected에서 반려행은 **[다시 작성]** 파란 버튼) + [댓글] + [⋯].
- 빈 상태: 점선 박스 "오전 · 완료된 업무가 여기에 쌓입니다".

#### 부분 반려(rejected 모드) 행 처리  ★중요
- `taskRejects`(반려된 업무 id 집합)를 읽어 행 렌더 분기:
  - **반려 행**: 좌측 파란 띠(`box-shadow: inset 3px 0 0 #3B5BDB`) + 연한 파란 배경(`#F5F8FF`) + 빨강 "↩ 반려 사유 · …" 콜아웃 + **[다시 작성]** 활성.
  - **그 외 행**: 흐림(opacity .5) + 액션 버튼 제거(읽기 전용).

#### 커뮤니케이션 기록 카드
- 기존 기록 리스트(유형 배지 + 상대방 · 시각 + 요약 + 첨부 칩(선택)). **유형 배지는 작은 둥근칩(높이 22px, 라운드 6px, `#EEF2FF`/`#2F49B0`)** — 원형 금지. (전역 CSS 덮어쓰기 방지를 위해 width/height/aspect-ratio 명시.)
- **"＋ 커뮤니케이션 기록 추가"**(점선 버튼) → 인라인 폼: 유형 칩(메일/통화/구두/카톡/회의/메신저, 필수) + 상대방(필수) + 시각(선택) + 내용 요약(필수) + 파일첨부(선택) + 취소/추가. 추가 시 목록 상단에 prepend.
- "오늘 커뮤니케이션 없음" 체크박스.

#### 일일 코멘트 카드
한 줄 정리 textarea(0/500 카운터).

#### 근태(vacation) 모드
- "오늘은 휴가로 처리할까요?" + "← 업무 작성으로" 복귀 버튼.
- 유형 셀렉트(연차/반차/병가/공가/휴직/기타). **유형별 사유 필수/선택 분기**: 병가·휴직·기타 = 필수(빨강 `*`), 그 외 = 선택. 비필수 전환 시 입력값 캐시 보존.
- 사유 textarea(최대 10,000자). **한도 도달 시**: 카운터·보더 빨강 + "⚠ 최대 10,000자까지 입력할 수 있어요" 1회 안내.
- 필수 유형 시 "이 사유는 승인자(그룹장)에게도 표시됩니다" 골드 콜아웃 + 파일첨부.

#### 하단 sticky 액션바
반투명 흰 배경 + blur. 좌측(rejected 시) "반려된 업무만 편집할 수 있어요". 우측 [임시저장] + **[제출하기]**(view 시 "제출 완료"·회색 비활성).

#### 제출 확인 모달
"오늘 보고를 제출할까요?" + 완결/지연/미완 카운트. **미완료 N건 있으면** 경고 + **"미완료 N건을 내일 할 일로 이월" 체크 옵션**. 취소/제출하기. 제출 시 view 모드 전환(+이월 시 토스트).

#### 업무 수정 모달 (⋯ → 수정)
업무명(필수) + 프로젝트(선택) + **예정 시간 / 소요 시간 셀렉트** + **상태 셀렉트**(예정/진행중/완결/지연). 안내: "상태를 완결·지연으로 바꾸면 마감 시각이 부여되어 오전/오후로 자동 분류됩니다." 저장 시 업무 갱신(상태→완결/지연이면 doneTime 부여, 예정/진행중이면 doneTime 제거).

#### 업무 삭제 확인 모달 (⋯ → 삭제)
"이 업무를 삭제할까요? / 삭제하면 오늘 보고서에서 제거되며 되돌릴 수 없습니다." 취소/삭제(빨강).

### 업무(task) 스키마
```
Task {
  id: string
  title: string
  project: string            // "" 가능
  plan: string               // "예정 09:00 · 2h" 형태(표시용)
  status: '예정'|'진행중'|'완결'|'지연'
  doneTime: string|null      // "HH:MM" — 마감 시각(완결/지연일 때). 12시 기준 오전/오후 분류
  hold?: string              // 지연 사유
  detail?: string            // "예정 2h · 실제 2h 10m"
  night?: boolean            // 야간 업무
}
```
**오전/오후 분류 규칙**: `done = (status∈{완결,지연}) && doneTime`. `done`이면 `parseInt(doneTime.hh) < 12 ? 오전 : 오후`. `night`는 별도 바구니(야간 토글 on일 때만).

### 부분 반려
`taskRejects: { [taskId]: { comment } }`. 검수 행 반려 시 추가, 작성 rejected 모드에서 해당 업무만 편집 가능.
